# 字符工具完整接口范围提案 0.1.0

这是提供方范围提案，**不是冻结协议、WASI 适配、插件包或 Host 支持声明**。不修改 rc.1，也不把 JSON 字符串藏进 input.text。operation.schema.json 只描述四项操作的输入形状；没有定义可执行的 Host 调用信封、资源传输或预算。

ASCII 查询和字符分类检索分别使用 query、query/category；横幅使用 text/ink，保留40码点及单ASCII可显示填充字符；图片使用资源引用和8–120宽度。资源引用只是提案字段，必须由Host核验插件/场景/操作/授权/有效期，任何非空字符串都不自动得到读取权限。当前没有可用的资源调用API。

图片完整范围保持PNG/JPEG/WebP、10MiB、20MP、高最多120行。资源传输不得塞入原48KiB请求或私读路径；20MP RGBA约80MB，超过原64MiB预算且未计解码/缩放峰值。因此runtimeBudget明确为null，待测量及共同协商；未定义的预算不能当作无限或现有profile已经支持。不能通过减小原图片范围消除这一缺口。

读取、复制、保存是独立操作。复制只发送用户明确选中的完整值，不读取剪贴板。保存先预览内容/目标，保留create_new语义；已有文件必须报冲突，取消零写入，撤权/场景/结果修订变化在提交前重新检查。保存失败保留结果，避免丢失用户工作。宿主可以在明确授权下保存数据，并非一律只读。

接力必须显式选择目标字段：query、text或资源引用，保留其他草稿，完整预览后再填入，不自动生成或覆盖文件。图片引用只能在授权范围内转交，不能把路径冒充资源引用。旧结果需标记过期，取消不改变当前输入和结果。

verify_character_proposal.py 实际校验JSON Schema、严格解析、源工具版本、数据分类及正反向输入形状。该验证不执行算法、不证明资源权限、运行预算、Host生命周期或Pi授权；整体三工具仍未交付。共享核心测试和原生质量链另行记录。
