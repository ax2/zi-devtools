# 多字段纯计算提案 0.1.0

状态：**提供方提案，未冻结、未被 Host 支持、无运行模块**。不修改 `contracts/studio-devtools/v1`，不把结构验证当作操作交付。拟使用独立 `compute.fields.v1` 与 `1.1.0-proposal.1`，必须显式协商成功才可调用；旧 Host 拒绝，不能回退成旧 `input.text` 中隐藏 JSON。

| 源工具 | 提案操作后缀（前缀 `devtools.compare.`） | 必填字段 | 原生完整范围与保留语义 |
| --- | --- | --- | --- |
| 正则 | `regex.matches` | `text`、`pattern` | 现有 Rust regex 引擎，最多展示 100 匹配、捕获组及字节位置，单值截到 120 码点；原生 pattern 4096 字节、text 2 MiB |
| 文本差异 | `text.diff` | `left`、`right` | 现有逐行 unified diff、三行上下文、原文/修改后标题；原生每侧 128 KiB/5000 行、500ms diff 算法期限 |
| JSON 差异 | `json.diff.ordered`、`json.diff.unordered` | `left`、`right` | 现有 JSON Pointer 转义、增删改、数组按下标或忽略顺序但保留重复值；原生每侧 1 MiB、10000 差异、8 MiB 文本结果 |

JSON 差异两个模式用不同能力，用户显式选择；不用默认值隐藏模式，不因当前接力尚不支持必填 bool 而丢弃任一模式。源工具版本从 `docs/tools.json` 记录在 `proposal.json`，并非三项工具已迁移或已验证运行预算。

`request.schema.json` 定义拟议完整请求：显式提案版本、自身包 ID、1–128 UTF-8 字节场景 ID、四个能力白名单、`commandId:null`、严格的具名输入。禁止未知/重复字段、非字符串、隐式类型转换、非 JSON 常量和非法 UTF-8。`result.schema.json` 保留原有输出四字段结构和五类错误码，但版本匹配新协议；结果字段中只能一侧非空，完整序列化限制另行校验，尚未声称完成协商。

插件拟议每个文本字段最多 8192 UTF-8 字节，正则 pattern 最多 4096；总输入最多 16384 字节，请求/结果各 48 KiB。模块 2 MiB、内存 64 MiB、guest stack 2 MiB、10M fuel、五秒；预算必须由实际共享核心/WASI/独立引擎及真实 Worker 验证后才能称可交付。正则编译、密集捕获、差异算法与序列化膨胀都可能超过预算，不以 schema 正例推定能够执行。不得为了通过预算悄悄缩减完整操作语义。

现有文本差异使用 `Instant` 的 500ms 算法期限；将它移到 WASI 可能引入时钟导入。该依赖必须先由 Host 明确协商单调计时能力，或共同定义可验证的确定性步骤预算及版本化行为，不能隐含增加时钟权限，也不能宣称 fuel 与原时间期限语义完全等价。此项作为真实运行交付阻塞记录。

## 字段接力

拟允许用户明确选择 pattern/text 或 left/right，源结果只映射这一字段；其余必填文本由用户明确填写并完整预览。pattern 的 4096 字节限制独立检查。不会从 schema 默认值、私有草稿或其他窗口补齐输入，不自动运行。预览保存来源身份、目标版本/场景、完整字段快照及修订；确认时复核权限、版本、源/目标修订和预算，取消零提交。旧结果、当前草稿和另一侧内容必须保留。

Studio 已报告 `zicode.studio.result-transfer/1.1-candidate` 的源码映射候选，只代表接力候选，**不等于 Worker 已支持本提案**；实际协议协商、运行及生命周期需分别验证。View/Pi 应展示每字段语义和限制，不用单一 `text` 假装完整支持多输入。

## 验证与后续

`python scripts/verify_fields_proposal.py` 用实际 JSON Schema 校验 68 个请求和 17 个结果正反向结构向量，另检查非法 UTF-8；覆盖每字段缺失/类型/字节边界、身份/版本、重复键、未知字段及完整序列化大小。仅验证提案结构和预算，不执行原生算法或 WASI。
