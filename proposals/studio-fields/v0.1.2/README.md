五项操作及字段范围继承0.1.1。新增文本差异采用完整同仓 `zi-diff-core`：每字段8192 UTF-8字节，仍遵守原5000行限制；500ms算法截止可能产生近似差异，不是整体调用时间保证，也不产生自定义TIMEOUT错误。请求/最终结果48KiB，总输入16384字节；10M fuel、5秒、64MiB内存、2MiB栈和2MiB模块预算不放宽，均须另行实测。

新增的时钟要求是运行环境协议约定，不是文件或网络权限：Host必须显式协商本版，并为text.diff在整个调用期间持续提供 `wasi_snapshot_preview1.clock_time_get` 的单调时钟（clockId=1）。Host应在调用前检查支持情况，不能依赖请求内容作为授权或支持证明。实验适配器额外预检实际系统调用；不支持时返回 `RUNTIME_UNAVAILABLE`，不调用算法。预检不能弥补调用中途撤除时钟；Host必须保持本次运行的时钟策略稳定。

独立 `zi-compare-wasi` 仅接受proposal.3，旧版本明确拒绝。文本差异直接调用完整核心；另四操作在进程内复用 `zi-fields-wasi` Rust库，仅内部规范化协议标识并重封装结果，不调用旧Host协议、EXE或HTTP。结果报告和JSON转义后的完整信封均检查字节预算，不截断后返回成功。旧四操作模块未重新生成。
