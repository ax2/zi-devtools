# 六项View操作的发现与定位提案

此目录仅是提供方提案，不进入插件manifest，不声明未被Host实现的profile，也不形成Pi可调用capability。0.1.2候选仅使用这一已有应用目录合同。

operations.json给出六项稳定ID、标题、类别、别名、用途、主View及拟定位DOM目标；DOM目标用于实现人员对账，Host不得解析HTML猜测操作。vectors.json给出每项五种情况，共30条未来一致性向量：已定位、未知ID、慢回调、停用、版本变化。它们尚未在Host或View运行，不能标作通过的运行证据。

## 定位约束

定位请求不能携带目标文本、模型参数、origin、凭据或自动执行标志。绑定requestId、插件版本、场景、工作区和View实例；过期或不匹配的回复不改变焦点、最近使用状态或另一个页面。实例重建、场景切换、卸载与停用同样取消待定位状态。夹具1000ms仅是测试时间，不要求生产采用该值。

慢回调不能仅在Host忽略回执：View应用焦点前也必须确认请求仍有效。Host需给出有效期或取消/确认机制；在协议明确前，不加入临时自创SDK回调。若忙碌会禁用待定位按钮，应返回unsupported并保留现有请求及草稿，不强制聚焦不可交互控件。

health/info/metrics定位可选择端点但不得点击提交；summary定位可显示空状态。generate与models定位不调用模型服务。HTTP和模型生成均保留原有逐次用户确认。向量draftChanged=false指用户文字资料、origin和模型选择不得改动；显式端点定位允许改变端点选择。

## 实现与验收顺序

Host先确定精确版本化字段、取消语义与回执路由并完成隔离生命周期测试；提供方再增加View处理器及匹配profile，分别验证所有向量，然后在原生界面检查搜索、收藏、最近、焦点、窄屏和主题。当前整应用入口可独立推进，六项单操作定位保持未交付。
