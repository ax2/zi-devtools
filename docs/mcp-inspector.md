# MCP 协议调试台（Stage 26 开发中）

从工具首页搜索“MCP”或左侧“MCP 协议调试台”进入。填写本机 MCP stdio 服务的绝对 EXE 路径；参数为 JSON 字符串数组，例如 `["C:\\path\\server.js"]`，适用于把脚本路径作为 Node/Python EXE 参数传入。不通过 shell 执行命令。选择目标后点击“检查服务能力”，会建立短会话，完成初始化、协议版本校验，然后按服务声明的能力读取 tools/resources/prompts 分页列表。本操作不会读取资源正文或调用工具。

选择工具后可查看它声明的 `inputSchema`。在“调用参数”填写 JSON 对象，点击“准备调用选中工具”，再确认启动服务及发送参数。调用前会重新初始化和枚举，工具未出现在当前服务清单中时拒绝调用。工具响应仅在当前应用进程中显示。输入框内容、连接目标和结果不会写入配置或长期历史。子进程只继承必要的系统路径环境，不继承应用环境里的 API key 等自定义变量；依赖这些变量的服务器暂需后续显式环境配置。服务进程本身是用户选定的代码，本功能不提供沙箱；只向可信目标发送参数。

每次操作总时长：检查 15 秒，调用 30 秒；单条消息最多 1 MiB，请求最多 256 KiB，列表每类最多 128 项、8 页。点击“停止并退出进程”会取消当前操作；Windows 使用 kill-on-close Job Object 清理被启动的进程树。服务 stderr 不显示，避免将其日志中的敏感数据带入界面。此首版只支持 stdio 的行分隔 JSON-RPC；没有持久连接、Streamable HTTP、资源读取、prompt 获取、自动 Agent 调用、参数表单或通用协议日志。
