# 本机 RAG 评测

先在“本地知识源”添加并扫描文件，再到“增量知识索引”手动同步。评测工作台读取固定 JSON 样例集，每题写清问题、检索词、预期知识源名称与该来源下的相对文件路径。评测集最多 10 题、32 KiB；输入仅保留在当前程序内存。示例：

```json
{
  "version": 1,
  "cases": [
    {
      "id": "access-code",
      "question": "银杉项目的准入码是什么？",
      "terms": "准入码",
      "expected_source": "项目资料",
      "expected_relative": "notes/guide.md",
      "expected_answer_contains": "ZX-42"
    }
  ]
}
```

`expected_source` 必须与一个已添加知识源的名称完全一致；`expected_relative` 必须是该来源当前扫描快照里的路径。`expected_answer_contains` 可省略。点击“校验评测集”会检查字段、重复 ID 和来源。选择 Top 3/5/8 后，点击“运行检索评测（不联网）”仅使用本机索引和原文件版本校验，统计预期文件是否进入本题证据列表。若需要测试模型，填写本机 Ollama `/api/chat` 或 OpenAI 兼容 `/chat/completions` 回环地址及模型名称，再明确点击“运行本机模型评测”。

模型模式复用[带引用的知识问答](knowledge-answer.md)的证据与引用编号校验。没有可核验证据时不会发模型请求；逐题失败会显示原因并继续后续样例，取消会停止余下评测并保留已完成报告。报告分别统计来源进入 Top K 的题数、模型有效引用指向预期文件的题数，以及答案包含指定字面片段的题数；没有填写字面预期的样例不会参与该项判定。相同样例集可换模型或 Top K 重跑，并保存不同文件手动比较。

报告默认只在内存中。用户明确指定新 `.json` 路径并点击“保存报告”才会写入，已有文件拒绝覆盖。报告包含问题、检索词、预期文件、可选预期片段、证据来源与文件哈希、答案引用编号、模型简短答案和统计结果；不导出证据全文。选择保存位置时应考虑其敏感性。模型模式会将问题和限长证据片段发送到用户选择的本机模型服务；该服务自己的日志和保留行为由其设置决定。

这些指标是回归检查：来源召回并不等于正文支持答案，引用编号有效也不证明模型陈述真实；字面包含只检查字符，不衡量语义。当前检索仍为关键词召回，向量混合检索、语义事实核验和自动批量联网评测尚未实现。
