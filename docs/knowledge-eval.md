# 本机 RAG 评测

先在“本地知识源”添加并扫描文件，再到“增量知识索引”手动同步。评测工作台读取固定 JSON 样例集，每题写清问题、检索词、预期知识源名称与该来源下的相对文件路径。评测集最多 10 题、32 KiB；输入仅保留在当前程序内存。示例：

```json
{
  "version": 1,
  "cases": [
    {
      "id": "access-code",
      "question": "银杉项目的准入码是什么？",
      "terms": "准入码",
      "expected_source": "项目资料",
      "expected_relative": "notes/guide.md",
      "expected_answer_contains": "ZX-42"
    }
  ]
}
```

`expected_source` 必须与一个已添加知识源的名称完全一致；`expected_relative` 必须是该来源当前扫描快照里的路径。`expected_answer_contains` 可省略。点击“校验评测集”会检查字段、重复 ID 和来源。选择 Top 3/5/8，再为单路评测选“关键词”（默认）或“关键词 + 向量”。混合模式需先在“本机向量索引”用 Ollama 嵌入模型同步，并在评测页填写相同模型、回环 `/api/embed` 地址与 25/50/75% 关键词权重。点击“运行检索评测”统计预期文件是否进入本题证据列表。若要测答案，另填本机 Ollama `/api/chat` 或 OpenAI 兼容 `/chat/completions` 地址及问答模型，再明确点击“运行本机模型评测”。

“同题对照”始终在相同样例集、Top K 和当前知识源快照上顺序运行关键词与混合检索，不调用问答模型。逐题显示预期文件在两路证据中的名次、耗时和错误；只对两路都成功的题统计各自命中、仅单路命中、双方命中/未命中以及平均倒数排名（MRR）。未命中的倒数排名为 0。模型/向量索引错误的题不进入这些成对指标，以免把故障算成质量下降。耗时仅供诊断，因为混合侧需要本机模型生成查询向量；评测期间文件或模型若变化，应重新扫描、同步后复测。

模型模式复用[带引用的知识问答](knowledge-answer.md)的证据与引用编号校验。没有可核验证据时不会发模型请求；逐题失败会显示原因并继续后续样例，取消会停止余下评测并保留已完成报告。报告分别统计来源进入 Top K 的题数、模型有效引用指向预期文件的题数，以及答案包含指定字面片段的题数；没有填写字面预期的样例不会参与该项判定。相同样例集可换模型或 Top K 重跑，并保存不同文件手动比较。

报告默认只在内存中。用户明确指定新 `.json` 路径并点击保存才会写入，已有文件拒绝覆盖。单路报告版本 2 记录检索策略、嵌入模型和权重，并包含问题、检索词、预期文件、可选预期片段、证据来源与文件哈希、答案引用编号、模型简短答案和统计结果；不导出证据全文。对照报告采用独立 schema，记录每题预期文件、两路名次/耗时/错误及成对统计，不包含问答答案。选择保存位置时应考虑其敏感性。混合检索把检索词发送给本机 Ollama 嵌入服务；模型评测还会把问题和限长证据片段发送给选定的本机问答服务，各服务的日志和保留行为由其设置决定。

这些指标是本机回归检查：来源召回并不等于正文支持答案，引用编号有效也不证明模型陈述真实；字面包含只检查字符，不衡量语义。十题以内的合成样例不能证明混合检索在一般语料上更好；语义事实核验和自动批量联网评测尚未实现。
