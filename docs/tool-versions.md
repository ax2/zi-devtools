# 独立工具版本

更新：2026-10-05。程序版本、工具版本、插件包版本、数据格式版本分别维护。

## 已接入

`docs/tools.json` 的每个目录条目包含 `tool_version` 与按时间追加的 `version_history`。工具库每行显示该工具版本，搜索结果也保留版本；悬停可读完整说明。生成清单显示已实现、开发中与规划项的独立版本，CI 检查版本格式、历史严格递增及当前版本与最后一条记录一致。

首次建档采用明确的当前基线：已实现条目 1.0.0、开发中条目 0.1.0、未实现规划 0.0.0。此基线不是重新验收全部工具，也不补造过去的版本历史。状态仍是判断可用性的依据；1.0.0 不代表没有已知限制，已验证范围以 scope 为准。

插件工具清单新增可选 `version` 字段（工具版本，不是插件包版本），现有示例已登记 0.1.0。旧清单仍可读取，未声明时显示“版本未声明”，不继承包版本或制造独立版本。修改示例或已安装清单的内容会改变 SHA-256，已启用插件依然需要复核并重新启用。

## 维护规则

1. 工具 ID 永久稳定，名称可变。仅程序其它模块变化时，不递增无关工具版本。
2. 版本格式为 `major.minor.patch`，各段为无前导零的 u32 整数。正式工具：不兼容改动增加 major，兼容功能增加 minor，修复增加 patch；0.x 开发中也遵守记录与递增要求。
3. 修改工具行为、依赖它的共用行为、数据格式或权限范围时，评估受影响工具并同步更新版本、scope 和历史说明。纯排版且无使用行为变化可不升工具版本。
4. `version_history` 追加日期、版本、用户可理解的变更；保留旧记录。更新工具状态不自动假定跨越 1.0，先做验收。
5. 运行 `python scripts/sync_tools.py` 与 `--check`；代码、清单、文档和阶段验证一起提交。

记录示例：

```json
{
  "tool_version": "1.1.0",
  "version_history": [
    {"version": "1.0.0", "date": "2026-10-05", "changes": "当前版本基线"},
    {"version": "1.1.0", "date": "2026-10-10", "changes": "示例：增加新操作；实际记录需有实现证据"}
  ]
}
```

## 后续接入

工具详情中的完整变更记录、升级前后按工具比较、保存结果的来源版本与运行环境指纹、插件工具历史记录仍待实现。工具版本不能替代数据库 schema、工作流文件版本或可执行文件摘要；历史结果不能因当前工具已升级而被自动改写。
