# 多窗口备忘录与日程

开发版 0.82.0-dev.49 起，备忘录和万年历与日程各为 1.1.0。从多个工具快捷方式启动、使用同一配置位置的窗口，共用同一份 `planner.sqlite3`。

后台约每两秒检查数据库及 WAL 的大小和修改时间，仅发现变化时异步读取受容量限制的完整快照。其他窗口保存的新建、修改、回收或删除记录可自动出现；不同配置位置的数据互不影响。隐藏窗口也会检查，以便发现新建的提醒。不是逐次文件变更的审计日志，不保证人为恢复文件时间和长度后的变化检测。

没有修改的当前记录会刷新；未保存的标题、正文、日期、时间和重复截止日期保留，原版本也保留。另一窗口修改或删除同一条记录时显示冲突提示。保存仍执行已有的 SQLite 版本校验，拒绝覆盖新版本；先复制需要的内容，再放弃编辑并重新加载。后台读取失败保留现有记录并显示提示，重试成功后恢复。后台读取与前台保存使用不同通道，过期读取结果不覆盖后来的前台操作。

同一数据库由一个窗口负责自动到期提醒。窗口内显示负责人状态；其他窗口仍可手动打开待处理提醒、确认或延后。负责人最小化或隐藏后继续工作，关闭或异常退出后由其他窗口自动接管。接管前重新读取记录，已确认或延后的提醒不会因接管而重新弹出；尚未处理的提醒可再次提示。所有窗口都退出后不提醒。独立时钟的计时器不受此协调限制。

协调使用数据库完整文件名追加 `.notify.lock` 的零字节文件及 Windows 文件句柄。文件保留不代表负责人仍在运行；进程结束时操作系统释放独占句柄。程序运行期间不要手动替换或删除该文件。此自动提醒协调只支持 Windows，也只约束协作版本；使用多窗口前退出旧版。

尚未提供后台系统服务、跨机器同步、多人合并编辑或自动合并冲突草稿。本改动不声称其他工作台的数据也具备同样保护。
