# 发布清单签名 0.4.0（开发中）

签名清单与程序更新页共用：新版发布附件若同时有 `update-manifest.json` 与 `update-manifest.sig`，先认证清单，再下载文件并核对摘要。历史 v0.81.0 没有这两件资产；仍可主动下载，界面明确显示只有完整性校验。签名文件缺失一半、未知公钥或认证失败时不回退。签名本身不触发安装。

## 清单协议与信任来源

JSON 清单 schema 1 最多512 KiB，声明程序 SemVer、40位源码提交、windows-x64、当前最低Windows主版本10、三个固定名称的发布文件及其长度/SHA-256，以及最多2048个内置工具的ID、名称、独立版本与实现状态。旧工具目录没有独立版本时保留 null，界面显示未记录，不按程序版本补造。此声明不等于已经验收每种Windows版本/每个工具；数据迁移、安装兼容检查仍需后续实现。

签名文件 schema 1 最多1 KiB，只有公钥指纹和64字节Ed25519签名的Base64。签名消息为固定域前缀 `ZiDevTools update manifest v1`（末尾NUL）加**原始清单字节**；任何格式化/空白变化都要重新签名。只接受程序编译时内置的 [公钥配置](update-trust.json)，公钥指纹是32字节公钥的SHA-256；不读取服务器传来的新信任根。未知字段、重复文件/工具/公钥、错误版本/摘要/大小/平台或超限拒绝。

下载版本与已认证清单版本必须完全一致，所选附件名称/大小匹配，内容摘要通过后才可预览/保存。工具差异后台计算一次，缓存不可变快照，显示新增目录项、版本/状态变化与移除；不检查用户安装的第三方插件目录。公钥与清单身份认证不等于Windows Authenticode代码签名、工具功能验收或恶意软件检测。

## 发布密钥和自动工作流

发布私钥仅放在当前Windows用户的凭据管理器专用publisher目标与本仓库 `ZI_DEVTOOLS_UPDATE_SIGNING_KEY` Actions Secret；源码、档案和日志只保存公钥/指纹。CLI不把私钥放进命令参数或输出；敏感拥有缓冲区在释放时清理。运行期程序只读取公钥，正常更新不会读取或创建发布私钥。

`publisher_key init` 创建或复用本机专用凭据，只输出公钥配置；`publisher_key upload` 通过标准输入配置本仓库Secret，已存在同名Secret时拒绝覆盖。`publisher_key check-env` 验证Actions注入的密钥与源码公钥一致，只输出公开指纹。此工具属于发布工程，不是普通用户工具库入口。

Release工作流生成MSI和校验和、安装/卸载检查后，调用 `sign_update` 计算三件附件摘要、签名并按内置公钥自验，最后发布六件资产。密钥缺失、失配或输出文件已存在会失败；不会继续发布无签名新版本。独立Update signing key工作流检查仓库Secret与内置公钥，不生成可安装更新。正式签名Release、下载后认证及安装全链路尚待首次正式版本验证；不把本地签名夹具称为线上签名发布。

本地签名：`cargo run --locked --example sign_update -- ASSET_DIR CATALOG_JSON VERSION SOURCE_COMMIT ABSOLUTE_OUTPUT_DIR --local-vault`。输出目录必须已存在；有界读取普通附件，输出元数据不覆盖。发布工作流从环境注入密钥而不是传私钥文件。清单签名只绑定提供的文件内容；构建版本/安装器身份和实际可运行性另由构建、MSI烟雾及发布验收检查，不能仅由文件名断言。

离线复核：`cargo run --locked --example verify_signed_update -- MANIFEST SIGNATURE ASSET`。同时核验内置公钥签名、版本命名、长度和文件摘要，不执行文件。SHA256SUMS验证仍可用于历史发布，但不能代替签名认证。

## 维护与未完成范围

保留原发布凭据和公钥，不通过删除凭据或覆盖Secret来修复构建。丢失密钥、撤销或轮换需要明确的新公钥分发/旧版迁移方案；配置目前最多8个内置公钥，没有远程自动信任或撤销服务。仓库中能修改签名工作流并访问发布Secret的人属于发布信任范围，不能声称该配置抵御仓库发布权限被接管。

便携完整包已接入明确确认后的退出等待、双EXE替换、失败/主动恢复，见[便携升级](portable-updates.md)。[MSI升级](msi-updates.md)已接入签名完整包准备、确认后原生安装和产品/双EXE核验；首次线上签名升级仍待验收。仍未提供增量补丁的签名分发与应用、断点续传、启动健康自动回滚和数据迁移恢复；最低系统只声明主版本，尚无完整版本/构建号兼容验收。签名认证完成不会让这些能力自动成为已实现。
