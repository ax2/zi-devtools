# 字符工具完整插件范围

状态：源码范围核对与设计，尚未实现或交付插件。以独立版 `src/character_tools.rs` 为基准；不能用文字横幅子集替代整个 ASCII Art 工具，也不能把页面选中复制当作已经完成宿主剪贴板授权。

| 工具 | 必须保留的既有功能 | 计算部分 | 等待明确的 Host 能力 |
| --- | --- | --- | --- |
| ASCII 码表 | 0–127 全表；十进制、`0x`/`0X` 十六进制、单个可显示字符和名称搜索；控制符与可复制字符区分 | 同仓共享名称、匹配规则和完整128项数据 | 仅对32–126提供复制按钮；主动点击、明确文本载荷、授权拒绝反馈 |

| ASCII Art 文字模式 | 5×7字形；大小写英文字母、数字、空格及既有标点；自定义填充字符；不支持字符用`?`替代并反馈数量 | `text`最多40个码点，`ink`必须恰好1个ASCII可显示字符；保留七行和尾部空格/换行 | 文本复制和另存TXT |
| ASCII Art 图片模式 | PNG/JPEG/WebP；10MiB文件、20百万像素；宽8–120字符、高最多120行；Triangle缩放、透明像素按白底、原亮度公式和字符梯度 | 解码、等比高度取整/夹限、缩放与灰度映射必须与独立版逐字节对照 | 用户选取的图片资源、解码/内存预算、结果复制与另存TXT |

ASCII 查询不能偷偷改变优先级：原UI先trim，十六进制/十进制成功解析优先于单字符匹配，因此输入`7`查询控制码7，而不是字符`7`。空白查询显示全部，空间字符可用`32`或SPACE名称查询。字符库的分类条件与搜索条件同时生效。

文字横幅需要显式的`text`和`ink`字段；字符库需要显式`query`和`category`。这些参数不能塞进旧`input.text`的隐含JSON，也不能固定填充字符或只提供某个分类以迁就单字段试点。可与多字段提案共同推进，但冻结的rc.1和现有提供方多字段草案不因此自动获得支持。

图片模式不能接收本机绝对路径后由Guest自行读取，也不能调用独立EXE/本地HTTP。需要Host公开且经用户授权的资源引用或明确的数据传递协议；读取、复制和保存分别授权，不默认允许目录扫描。TXT保存保留原`create_new`行为：目标已存在则失败，不覆盖原文件；授权取消或写入失败需有可理解的反馈。新的覆盖确认能力应另行设计并版本化。

现有compute试点的8192字节输入、48KiB结果、10M fuel和64MiB内存不足以直接表达或处理整个10MiB/20MP图片范围。单张20MP RGBA像素就约80MB，尚未计入解码/缩放工作内存。应协商资源/图片处理profile或Host共享解码预算，不能缩小既有图片范围后把工具标为完整迁移，也不能暗中扩大冻结compute预算。

页面应保持三种任务可发现：查ASCII、找字符、做字符画；字符画下再选择文字/图片。查询、分类、文字/填充、图片资源和输出草稿分别保留。数据在页面临时保存还是由Host持久保存，需按用户授权和统一会话接口明确；不以“必须只读/不落盘”限制整个平台。

验收必须覆盖：128项逐项数据和所有查询优先级；全部精选字符逐项一致及各分类/查询组合；字形全集、40/41码点、填充边界、替代计数和尾空白；三格式/透明像素/8与120宽度/文件和像素边界；复制授权拒绝、保存取消/已存在目标/失败保留；真实Host资源生命周期。未完成时按操作记录开发进展，整个工具保持未交付。
