# 超级剪贴板0.20.3（开发中）

程序0.82.0-dev.105。工具搜索“剪贴板”“连续复制”或统一前缀后V进入。默认不采集；点击开启后监听Windows剪贴板新变化，默认只读取文本，图片、文件引用和HTML富文本须分别另行开启。已有剪贴板不会主动导入；占用/无效/超限显示错误，极快事件可能遗漏。

## OCR识别语言选择（0.20.0）

图片预览在后台列出 Windows 当前已安装的 OCR 语言包，可从下拉列表选择识别语言，也可保留“系统首选语言（自动）”。列表项显示本机语言名称和 BCP-47 语言标识；语言选择只在当前图片预览会话生效，不写入设置或历史。查询失败时可手动刷新；默认语言仍可尝试。

切换识别语言会清除旧识别文本和接力选择。识别时由 Windows 按所选标签创建引擎，并检查引擎实际解析出的标签；语言包不可用或被解析到其他标签时明确失败，不静默回退。明确选择 OCR 接力时，来源标记也会包含所用语言标识。

## OCR工作线程稳定性（0.20.1）

语言枚举与识别统一交给一个常驻的本机 MTA 工作线程执行，避免短生命周期线程反复初始化/释放 WinRT 后再次创建 OCR 引擎导致进程崩溃。图片仍在本机处理，识别结果和语言选择的保存边界不变。

## OCR队列上限（0.20.2）

工作线程最多保留一个待处理请求；运行中和待处理的请求占满后，新请求会立即显示“本机 OCR 队列已满，请稍候重试”，不会在后台无限排队或保留多张待识别图片。稍后可重新启动识别或刷新语言列表。

## JSON记录组合（0.20.3）

组合格式新增“JSON记录”。每个已勾选的文本条目输出为一个对象，包含勾选顺序、正文、来源应用文件名、显示时间和标签；不导出内部条目 ID 或路径。输出仅包含明确选中的文本记录，沿用单条与总输出 1 MiB 限额，图片和文件引用仍不能混入文本组合。

预览会完整显示这些元数据，用户再决定复制或通过统一接力栏发送到数据工作台、备忘等目标。组合本身不自动写入历史或磁盘；接收目标继续使用各自预览、确认和保存步骤。

## 局部图片 OCR（0.19.0）

图片预览可选择“框选局部区域”，在预览图上按住鼠标拖出区域；松开后选择框映射回原图像素，区域最小为2×2像素。点击识别后，后台先从原图裁剪选区，再调用所选 Windows 本机 OCR；默认使用系统首选语言。没有选区时仍识别整图。截图和预览不会被裁剪或修改。

更改或清除选区会清除旧识别文本并取消该结果的接力选择，避免把上一识别区域的文字误认为当前结果。局部结果沿用原来的有界预览和手动接力确认；来源标记显示“局部”或“整图”。选区只保留在当前预览，不写入历史或磁盘。

默认历史仅存于本次程序内存，退出清空、不写盘；可主动开启本机保护保存，不联网。隐藏到托盘仍采集；私密暂停不补采，关闭采集保留会话历史直到退出。可配置实际进程来源排除及未知来源拒绝；敏感内容仍可私密暂停。来源只显示应用文件名，可显示未知，不保证识别所有密码或来源。

文本按内容去重，更新复制时间与来源，保留ID及置顶状态。最多500条、单条1 MiB、混合总预算32 MiB（图片含编码与RGBA容量）；超出时淘汰最旧非置顶内容，全部置顶导致不足时拒绝新增并提示。置顶条目优先显示，删除/确认清空可主动释放内存。

## 图片文字识别与工具接力（0.17.0）

在图片预览中明确点击“识别图片文字”后，后台调用 Windows 本机 OCR；按 Windows 用户首选语言选择识别引擎，不上传图片、不调用云端模型。若本机没有匹配的 OCR 语言组件，界面显示失败原因。超过系统 OCR 尺寸上限的图片会按比例缩小后识别；识别文本最多 1 MiB，空结果或超限结果不提供接力。

识别结果显示在当前图片预览中，默认只驻留当前运行内存，不进入剪贴板历史或保护快照，也不写入文件。用户可将结果明确设为“当前接力结果”，再通过页面顶部统一接力栏选择支持的工具；目标原有预览、接收上限和确认步骤继续生效，Agent 不会因 OCR 完成而自动生成计划、访问模型或 MCP。取消接力选择不会改变组合文本。来源图片被替换、移除或预览关闭后，旧 OCR 结果不能再接力；正在运行的后台结果会被丢弃。

OCR 运行、完成、失败或预览关闭后丢弃结果的状态也会显示在后台任务中心（工具1.2.0）。任务中心只保存通用状态摘要，不保存识别正文、图片或文件路径。

按勾选先后组合为段落、编号、JSON数组、CSV单列、Markdown清单或自定义模板，先看预览，再复制。Markdown清单按原顺序为每项加无序列表标记，多行内容缩进到同一列表项；CSV对可能的公式加单引号，原文不变；输出上限1 MiB。自定义模板只保留在当前会话，支持 {{index}}、{{text}}、{{source}}、{{time}}、{{labels}}，必须包含 {{text}}；未知或未闭合变量会报错，正文变量标记不会二次解析。模板最多16 KiB，完整输出仍限1 MiB。复制会替换系统当前剪贴板，本工具输出不回流采集，外部应用重新复制相同内容仍更新历史。关闭采集后复制使用原有UI剪贴板出口。

在历史视图下方可将当前搜索结果中的匹配文本一次加入组合选择。此动作追加到已有选择、不重复已选条目，且不影响筛选条件之外已选内容；空搜索表示全部历史文本。筛选结果按置顶优先、随后按历史列表顺序加入；图片不参与。按标签分组时每条记录只加入一次。组合仍受1 MiB上限，超限时保留选择并提示，不截断内容。

组合结果可通过现有接力入口发送到备忘草稿、数据工作台、Agent接力资料区和其他文本工具，沿用目标输入保护及预览；接力来源显示规范目录中的当前剪贴板工具版本、有限条目ID及去重后的来源应用文件名（最多展示4个，不含路径），正文不附加来源标记。交给Agent时会作为不可信会话资料，最多32 KiB，只驻留内存，且不自动生成计划、访问模型/MCP或保存记录。示例按钮追加合成示例，不读取系统剪贴板，不清空原有历史。

## 边界与后续

当前实现有界文本/图片/文件引用/HTML/RTF历史、标签检索、标签分组、自定义模板变量、JSON记录组合、Windows本机图片整图/局部OCR及可选本机保护保存闭环。JSON记录仅含用户勾选的正文、来源应用文件名、显示时间和标签，不含内部ID或路径；先预览再复制或接力。文件引用、HTML和RTF采集分别默认关闭；文件引用仅保存路径，可明确复制路径或送入现有文件确认页。富文本只保留HTML源码或RTF原始字节，不解析/渲染；OCR支持系统首选语言与当前设备已安装语言包选择，语言选择不持久化；置信度编辑仍待开发。图片 OCR 可由用户选作通用工具接力来源；自动粘贴和更细粒度的 Agent 上下文来源追踪仍待开发。Agent工作台1.4.0支持最多32项、多选导入有界UTF-8文本文件，批量校验通过后才整体加入。不能宣传为已完备，也不声称功能为市场独有。

通知与内存读写须有Windows独立窗口站的隔离验证；若创建不支持，明确记录未验，不回退测试到用户剪贴板。深浅UI仅使用合成示例截图。

本机隔离窗口站创建返回访问拒绝（5），测试在访问任何剪贴板前停止；不回退到交互剪贴板。公开Windows CI另外运行同一隔离夹具，结果单独记录。

## 本机保护保存（dev25）

展开“本机历史保存”，主动选择开启。文本、图片、标签、应用文件名、时间和置顶状态压缩后使用Windows当前用户范围保护，后台写入本机SQLite快照；数据库只保存受保护内容。默认路径为本机用户数据目录下ZiDevTools/clipboard/history.sqlite3，界面显示实际路径。同一Windows用户进程仍可能访问，不能把用户范围保护当作绝对隔离。

修改后静止1秒自动保存，持续变化最多约5秒开始一次保存；可立即保存。保存中新增的内容仍为未保存，下一次保存处理，不把旧快照的完成当作所有内容保存。删除、置顶与确认清空会同步下一次快照；清空后重启恢复空历史。退出及启动升级前检查后台/未保存历史，后台写入不能直接放弃；明确放弃未保存变化只放弃本次变化，此前保存的旧快照仍保留。

重启自动恢复此前已主动开启的历史，但不会自动开启剪贴板采集。恢复期间暂不允许修改。读取失败阻止覆盖，允许重试读取；已有会话内容时先确认替换并关闭采集，恢复后清除旧选择和接力结果。也可以明确选择“停止保存并删除本机历史”，删除受保护快照并停止保存，当前会话仍可使用。删除不是对磁盘介质的安全擦除承诺。

版本、字段、ID、文本/元信息及解压量有上限，拒绝链接/非普通文件、外国数据库、损坏内容、未知快照版本。只在用户主动保存时创建存储；后台失败停止自动重试并显示状态，原已保存历史和当前内存内容保留。保护、压缩及文件事务的测试仅使用合成内容与独立临时文件。

## 历史保留期限（dev26）

默认关闭。展开“历史保留期限”，设置1–3650天，查看当前拟清理条数，再确认应用与清理。以最近采集UTC计算24小时天数，包含恰好到期的条目，每分钟检查一次；置顶、未知UTC和未来时间条目不自动删除。关闭期限不恢复已经删除的内容。只删除本工具历史，不改变系统剪贴板或来源文件。开启本机保存时策略和删除结果随快照保存；关闭采集时仍检查保留期限，重启加载后也按已开启策略清理。

新记录包含首次与最近UTC时间，悬停来源时间可查看。重复复制保留首次时间，更新最近时间；系统回拨时最近UTC不倒退。schema2快照有界读取schema1，旧记录保留原来的月日时间，年份与UTC未知，不猜测。旧记录再次采集会获得最近UTC但首次仍未知。时间未知的旧记录仍计入500条/32MiB容量，需要时可手动删除。

保存为schema2后，dev25及更早版本不支持读取该快照，会显示读取失败并防止直接覆盖；回退程序不会自动降级快照。停止保存前请确认需要保留的历史。

## 应用排除（dev27）

展开“应用排除”，每行填写一个进程文件名（如example.exe），大小写不敏感，最多64个，每个256字节；不支持路径、通配符或分号列表。可勾选来源未知时不采集。编辑只是草稿，当前已应用规则与跳过通知数独立显示；选择“仅本次应用”不写文件，选择“保存并应用规则”先原子保存成功再切换规则，失败保留当前规则。退出/升级提示未应用草稿；可撤回草稿。

规则位于当前程序配置目录的clipboard-policy.json，最大32KiB，保存进程文件名和未知来源开关，与历史保存独立，不存正文或完整进程路径。重启加载规则但不自动采集。文件无效/读取失败时不能开启采集，允许仅本次应用新规则（保留旧文件），或明确勾选允许替换无法读取的旧规则再保存。仅采集关闭且无编辑草稿时可重新读取。

收到通知时先打开剪贴板并核对序列，读取实际ClipboardOwner进程名，匹配排除规则后直接跳过，在此之前不调用GetClipboardData读取文本。无法识别所有者则标为来源未知，使用独立开关；不推测前台应用或保证识别所有密码。规则变更与暂停共用门控，清除旧排队事件并跳过当前序列，不补采先前内容；不会删除已经保存的历史。跳过数量只统计通知，不透露正文，不等同于准确的复制次数。

## 图片历史（dev29 / 0.5.0）

开启历史采集后，另行勾选“同时采集图片”，默认关闭且重启不会自动采集。图片优先PNG，否则读常见24/32位未压缩DIB及明确32位RGB/alpha掩码的DIBV5；保留透明像素。BMP BI_RGB未定义的alpha按不透明处理。不支持的压缩、16/8位调色板、非常规掩码或ICC配置会拒绝，不能视为所有位图格式已支持。[标准格式](https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats)、[头与行跨度](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapinfoheader)。

图片最多400万像素、边长12000、规范PNG16MiB，原始剪贴板内存最多32MiB。共享500条/32MiB历史容量，图片同时计PNG编码及width×height×4的RGBA预算，置顶不足时拒绝新内容；文本仍1MiB/条。后台通知队列也限32MiB与64事件，消费、拒绝或清队归还预算。丢失事件显示反馈，不静默冒充全部采集。解码在监听线程且释放剪贴板锁/界面门控；暂停、规则或类型开关变更增加代次并清队，准备中的旧图片不能迟到入队。

规范PNG按像素去重，保留原ID/置顶及首次时间。图片可按来源应用搜索、置顶/期限/删除；只为当前选中图片后台准备缩略图和复制格式，最多一个准备任务及纹理，取消后的结果丢弃。图片不参加文本组合。预览可复制PNG+DIBV5（失败明确反馈）、无覆盖另存透明PNG，或发送图片工具后查看预览并确认目标，来源历史保留。只操作明确选择的图片，不创建接力临时文件或默认上传。

用户主动开启的保护保存同时包含图片，schema4仍DPAPI当前Windows用户范围。兼容读取schema1/2/3且无标签的快照，拒绝旧协议夹带图片、标签或声明尺寸/PNG/摘要不一致；恢复不开启任何采集。旧版本不支持schema4，回退前需备份并使用兼容版本处理数据。保存与策略独立。剪贴板图片OCR、剪贴板专属Agent上下文来源追踪/授权、更高分辨率/其他格式、多进程和真实长期用户路径验收仍待完成。

## 标签分类与检索（0.6.0）

每条文本或图片历史最多添加8个标签；标签去除首尾空白、最多32个字符且不得包含控制字符，同一条目内不区分大小写去重。条目再次复制时保留标签；可以逐个移除。历史搜索同时匹配正文、来源应用和标签；点击标签芯片可立即筛选，清除按钮可恢复全部结果。标签计入本机历史的32 MiB容量预算，不采集标签以外的内容，也不改变系统剪贴板。

## 标签快速筛选（0.7.0）

标签芯片可直接设置当前搜索条件；搜索框出现内容时显示清除按钮。该动作只改变当前会话的视图，不修改标签、不持久化搜索条件，也不触碰系统剪贴板。

## Markdown 清单组合（0.8.0）

勾选的文本按选择顺序输出为 `- 条目`；同一条目的后续行缩进两个空格，仍属于该列表项。CRLF/CR统一为LF。输出继续受1 MiB上限约束，先预览再复制，不改变历史原文；可直接粘贴到 Markdown 笔记、任务清单和项目说明。

本机保护快照升级到schema4。旧schema1/2/3中没有标签的数据可恢复为无标签历史；较旧schema中若出现标签字段则拒绝，避免静默丢弃。新快照仍需用户主动开启本机保存，旧版程序不支持读取schema4；回退前应先备份并使用兼容版本处理数据。

## 标签分组浏览（0.9.0）

历史视图可在平铺列表和按标签分组之间切换。分组按标签名称排序，每组可折叠并显示匹配条目数；没有标签的内容集中放在“未加标签”组。多标签条目会在所属的每个组中出现，搜索条件在两种视图中一致，所选内容仍按条目ID去重，因此组合结果不会重复。添加标签时自动切回平铺列表，避免同一条目在多个分组中显示重复的编辑框。此视图设置仅在当前会话生效，不改动历史和保存策略。

## 会话模板变量（0.10.0）

自定义模板支持 `{{index}}`、`{{text}}`、`{{source}}`、`{{time}}` 和 `{{labels}}`。每条所选文本独立展开并以换行连接；模板草稿仅在当前会话有效，不写入本机历史。必须出现正文变量，并拒绝未知或未闭合变量。展开正文不会递归解释变量标记。模板最多16 KiB，组合结果限制1 MiB；仍需用户预览并手动复制。

## 批量加入筛选结果（0.11.0）

“加入筛选文本”按当前搜索条件选取所有匹配的文本记录，避免逐条勾选；图片被排除，分组中重复呈现的多标签条目不会重复加入。操作是追加而非替换，可保留其他已选内容；再次点击不会重复选择。加入顺序与平铺历史一致：置顶记录优先，其余按当前历史顺序。结果组合仍经过原有容量校验、预览与手动复制。

## 批量添加标签（0.12.0）

选中至少两条文本后，可在历史列表上方输入一个标签并统一添加。动作只处理当前明确勾选的文本，不包含图片或未选中的记录；标签已存在的记录保持不变。执行前会检查所有选中记录是否仍有效、各自标签数量上限和历史总容量；任一项不符合时整批不修改，修正选择或标签后可重试。成功后按实际新增数提示，并写入已主动开启的本机保护历史。

## 文件引用与工具确认接力（0.13.0）

采集文件引用需要先开启历史采集，再单独勾选“同时采集文件引用”；默认关闭，启用/关闭时清除旧通知并跳过当前剪贴板，不追溯。文件名排除规则在读取路径前生效。每条最多64个引用、单路径最多32 KiB、总路径字节最多1 MiB，历史总容量仍为32 MiB/500条；只读取系统提供的CF_HDROP路径清单，不打开、检查、哈希或读取目标文件内容。文件路径可能暴露用户名、项目名或目录结构；只有勾选采集且用户主动保存本机历史时才会持久化。

文件引用独立于文本：不提供文本组合勾选，不进入模板/批量加标签，不显示正文预览；搜索可匹配路径。每条可单独复制路径列表。用户勾选文件引用后，可将去重的最多64个路径送入既有文件确认页，再选择支持的工具并确认；这只传递路径，尚未读取或处理。超出引用数或合计1 MiB的接力请求会拒绝。撤销选择不会改变原历史；删除文件引用历史不会删除来源文件。

保护快照使用schema5，可读取旧schema1–4，旧程序不能读取schema5。文件引用只在schema5记录；出现于旧schema会拒绝快照，避免静默丢弃。回退旧版前先保留/备份数据，并通过兼容版本处理快照。本机运行 `cargo run --locked --features ui-preview --example clipboard_fixture` 时，创建独立窗口站返回Windows错误5，发生在任何剪贴板访问前；未回退到交互剪贴板。公开CI在基线提交 `65f9aa63c831a4540bdd5731aa4da3de76dbd4b8` 的运行 `38426201821` 通过了文本/图片隔离夹具，但该提交不含本地未提交的CF_HDROP改动，因此不能证明文件引用读取已通过原生验证。CF_HDROP夹具已并入同一CI入口，需在这些源码改动进入CI后读取新的运行结果。

## HTML富文本与纯文本回退（0.14.0）

HTML采集需在历史采集开启后另行勾选，默认关闭；切换时清空排队事件，不追溯当前内容。只读取 Windows `HTML Format` 的 CF_HTML 片段，最多2 MiB，并同时保留最多1 MiB的 Unicode 纯文本回退。先应用来源进程排除，再取任何格式数据。CF_HTML 偏移按字节严格校验；支持 `StartHTML=EndHTML=-1` 的无上下文片段，以及 CRLF、LF、CR 标头换行。单边 `-1`、指向标头内部的片段偏移、越界、超限、无效UTF-8或含零字符均拒绝。应用不会渲染或执行捕获的HTML；搜索可匹配片段源码。

历史预算同时计算纯文本回退与HTML片段，仍受32 MiB/500条约束。卡片可分别复制纯文本或原富文本；富文本复制会写入 CF_HTML 和 `CF_UNICODETEXT`，仅在用户点击时替换系统剪贴板。保护快照升级为schema6并兼容读取1–5；schema1–5若包含HTML字段即拒绝。旧程序不支持schema6，回退前先备份并使用兼容版本处理历史。

验收边界：模型、CF_HTML偏移、受保护快照、界面和夹具编译已验证；原生夹具使用随机具名窗口站、CWF_CREATE_ONLY与仅所有者可访问的安全描述符，避免附着既有站或开放给其他用户。Windows只允许Administrators组成员创建具名站；本机非提升令牌返回错误5，发生于任何剪贴板访问前。自动生成站名的尝试发现该会话站已存在，CWF_CREATE_ONLY按设计拒绝复用。故HTML格式读写与来源排除的原生集成仍未验证，需在提升管理员环境运行；不回退到用户真实剪贴板。

## CF_HTML无上下文格式兼容（0.15.0）

按 Microsoft CF_HTML 规范，复制内容可以不带外层HTML上下文，此时 `StartHTML` 与 `EndHTML` 必须同时为 `-1`；头部行结束符允许 CRLF、LF 或单独 CR。本版本兼容这些格式，同时要求 `StartFragment` 位于 `EndFragment` 标头之后、片段范围不越界且仍通过 UTF-8、零字符与2 MiB上限校验。HTML仍只作为源码保留，不解析执行或渲染。

## RTF富文本（0.16.0）

RTF采集有独立开关且默认关闭；切换会清空旧通知并跳过当前剪贴板，不补采。Windows将 `Rich Text Format` 作为注册剪贴板格式；仅在来源排除通过后读取该格式。原始RTF有2 MiB上限，并验证基本RTF头部和结束大括号，但不做语法解析、渲染或执行。若剪贴板同时提供 `CF_UNICODETEXT`，会另外保留最多1 MiB的纯文本回退；仅有RTF时也可留空回退。HTML和RTF都另行开启时，同一来源条目可同时保存两种格式。

RTF、HTML与纯文本回退共同计入32 MiB历史及通知队列预算，可搜索纯文本回退/来源，并从同一卡片分别复制纯文本、HTML或RTF。读取时移除剪贴板载荷末尾的NUL终止字节；历史保存RTF正文，显式复制时再写入一个终止零字节。保护快照使用schema7，以标准Base64在受保护的JSON快照中保存有界RTF原始字节；schema1–6可继续读取，但出现于旧schema的RTF字段会拒绝，旧程序不能读取schema7。

RTF数据验证边界较基本：未解析RTF控制词、嵌入对象、字符集或外部引用，因此不会在应用中渲染；对含恶意/异常RTF的内容再次复制仍可能由目标应用解析。复制前只验证有界字节和基本包络，用户需确认目标应用可信。隔离窗口站夹具覆盖默认关闭、启用/关闭不补采、精确字节回读、来源排除先行及本工具复制回流抑制；它只以CWF_CREATE_ONLY创建随机具名站并为所有者设置独占ACL。当前非提升令牌被Windows拒绝创建具名站，在访问剪贴板前退出；不得改用用户真实剪贴板。

`0.13.0` 的文件引用字段为路径字符串；schema5沿用当前Windows用户保护和压缩保存。schema1–4保持原解析规则，不能包含新字段。历史不启用本机保存时仍仅驻留内存并在退出后清除。
