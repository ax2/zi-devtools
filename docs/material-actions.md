# 统一材料与动作：下一轮实现契约

状态：规划，2026-10-08。本文不表示当前流程已支持文件、图片、插件或Agent写入。

## 当前代码与缺口

`src/text_flow/material.rs`只有Text和Table；`src/text_flow.rs`格式1/2从文本开始，串行单输出、最多16步。`src/text_flow/files.rs`主动读取/保存，文件只是输入输出通道；`src/app/handoff.rs`与`src/image_tools/relay.rs`各自提供结果接力。它们还不是统一文件/图片材料模型。现有文本/表格配方必须继续可用，不强行重新保存。

用户允许本地保存及主动修改数据；本地优先不等于永远只读。新接口要能表达写操作，同时让普通纯计算保持便捷。

## 用户流程

1. 拖入文件、粘贴、从另一工具送入结果或选择已有材料，建立独立工作实例。
2. 操作搜索优先显示可以直接处理当前材料的动作；需要转换时展示可选转换步骤，用户选择后再加入，不悄悄改变内容。
3. 一次执行可以输出多个具名材料，例如压缩图片、缩略图和尺寸报告。结果卡显示来源、实际格式、大小、工具版本和状态；每件结果可预览、复制、保存或接力。
4. 默认新增目标；用户可以明确选择覆盖或批量修改。运行前显示将修改哪些文件、是否可恢复、预计资源及所需权限。纯计算不反复询问。
5. 失败定位到具体步骤/文件，保留已完成输出；取消停止后续操作，已落盘成品不因取消被删除。部分成功不能显示为全部完成。

## 材料数据模型

材料外壳包括稳定ID、显示名称、类型、媒体类型、实际字节数、来源工具及版本、创建时间、有效性和存储状态。预览仅是缩略副本，执行和保存不能使用截断预览。

第一轮保留Text/Table，增加File与Image。File保存本次明确选定的普通文件引用及身份快照；路径不是读取授权。读取时重新检查文件身份和边界，源文件被替换时要求重新确认。Image区分编码文件与像素数据，携带尺寸/透明通道/编码格式，解码前检查像素与解码内存预算。不能把任意二进制自动解释成UTF-8。

材料内容按需读取；文件大小、像素数、打开文件数、单次任务与总结果预算分别配置和检查，避免给所有媒体套用文本1MiB限制。超限明确说明可拆分/降低尺寸/调整允许范围，不无条件一次读入内存。

存储允许临时内存、用户指定文件、主动启用的本地材料库。删除库记录与删除原文件分开；清理只处理库拥有的缓存。退出后恢复草稿和材料引用不会自动执行、联网或恢复写权限。

## 动作及权限模型

动作声明稳定ID、算法版本、输入端口、具名输出端口、参数schema、效果（纯计算/读文件/新增文件/覆盖/数据库写入/联网/系统操作）、预算与取消能力。首轮保持串行链，先支持多输出及明确选定下一步的输入端口；分支图和并行执行后续实现。

权限绑定动作版本、参数摘要、具体资源及效果；变化后重新审核。用户可记住明确范围内的选择，例如指定目录的新增文件，不等于允许覆盖、删除或任意联网。插件和Agent共享此执行层，不绕过原生限制。模型建议本身不能授予权限。

新增文件沿用`local_files::save_new_moved`完整暂存与不覆盖发布。覆盖是独立能力：冻结变更计划、核对目标身份、按策略建立恢复副本，再提交；无法恢复的操作在确认前明示。恢复不能覆盖用户后续修改，也不能把所有外部命令声称为可撤销。

## 迁移顺序及验收

| 轮次 | 实现 | 真实验收 |
| --- | --- | --- |
| A | 共享材料外壳、文件身份、文本/表格适配 | 旧格式1/2往返；中文路径、删除/替换/链接、超限与取消；预览截断不影响完整执行 |
| B | 具名多输出及文件读取/编码/哈希动作 | 文件→哈希报告和原文件两件输出；选择任一输出接力；失败保留来源，无隐式执行 |
| C | 图片适配与图像动作 | 截图透明PNG→裁切/压缩WebP→尺寸报告；超大像素拒绝；透明度、实际格式与文件大小检查 |
| D | 主动材料库及跨运行检索 | 重启后检索/预览/选择；删除记录不删除原文件；失效引用明确反馈；凭据和权限不恢复 |
| E | 范围授权写入与恢复 | 新文件竞争不覆盖；主动覆盖/批量修改预览；冲突、部分失败、取消与适用恢复 |
| F | 插件/MCP/Agent适配 | 真实插件及协议输出进入同一模型；权限逐步核对，取消/超时；不同版本隔离；完整宿主链单独验收 |

第一轮先交付A/B的实际工作台能力，再扩展图片与写入。开发中每件动作维护工具版本、已实现范围、测试和截图，不能仅有schema就标为实现。Studio宿主由专门会话推进；本仓库仅负责独立算法、公共接口和候选插件交付。

## 首轮基础进展

`src/material_files.rs`已提供主动选择的内存文件引用、OS文件身份与大小/修改时间复核、按动作预算分块SHA256及原文件/报告双输出。基础测试和严格Clippy通过；尚无UI、统一端口或跨工具接力，不标为可用工具。文件身份检查不是外部写锁。

## dev82：文件校验的实际双输出

批量文件校验复用文件材料身份核验，保留SHA256/SHA512、进度、取消和部分失败结果。文件选择支持原有拖入/路径及多文件选择器。每个成功结果可选择校验报告（版本1 JSON，含文件名、字节数和双摘要，不含完整路径），通过顶部统一结果接力送入文本、备忘或流程等既有目标。来源仍保留。

“原文件 → 编码检查”冻结此文件引用，显示目标、大小与替换草稿说明；返回保留编码检查现有草稿。确认时重新核对文件身份及8MiB上限，再进入编码检查，不自动读取、转换或保存。主动读取继续验证身份；源文件删除、替换或改变拒绝读取。超出8MiB的文件仍可哈希，但不能进入编码检查。

这是现有工具间的实际文件引用/报告输出，不等于通用配方端口、多输出分支图、材料库或图片/插件/Agent平台已经完成。

## dev83：取消与失败保留

原文件接收确认支持Esc或点击遮罩取消，与“返回”一致。取消保留源报告和目标现有路径、编码选择、原始字节、解码内容及转换预览。接收时文件删除/改变导致失败，目标仍保持原有草稿，不把失败误标成已接收。

## dev86：图片信息报告的实际接力

已有单图/编辑/截图图像接力之外，新增冻结图片信息JSON报告，后台以当前实际编码结果优先提取尺寸、透明度、格式/精确字节数和来源版本链。未编码材料不估算文件大小。Images页统一文本接力可将报告交给JSON等或备忘草稿；确认接收不自动执行/保存。按来源工具保留报告；材料/图片模式变更抑制过期返回，旧报告保留可查看但不可误发送。批量/元数据报告、通用图像端口、材料库及执行配方继续开发。

## Java/Django共享纯计算核心

`zi-diagnostics-core`提供11项导入报告动作，桌面Java/Django模块重用相同代码。分析源码与dev83原算法完全一致，原诊断回归保持；环境采集/执行、文件获取、联网等仍需对应Host能力。`zi-diagnostics-wasi`命令适配器实际完成29组原生/WASI逐字节一致性验证，含全部11能力的结果断言及错误/预算边界。自包含分类View实际以公开SDK替身连接WASI，完成11入口、双主题/响应式、草稿/失败保留与过期/超时验证。诊断schema及新增错误码为提供方提案，尚未获Host确认。unsigned候选目录提供模块/View/元数据/schema/许可证及外部摘要证据。插件迁移目录逐项列出sourceToolId、工具版本、操作范围、core/adapter版本和未交付原因；正式签名和真实Host生命周期仍未验收。

## dev90：批量成功图片的实际接力

成功保存项可以逐项选择，经保存时的字节数/SHA-256及本次普通文件快照核对，预览确认后送入转换或裁剪。失败/未处理/缺摘要/任务中禁用；取消及读取失败保留输出，目标已有工作需明确替换，不自动编码保存。原图与清理预览及批量报告接力已逐轮实现；这仍不是统一图片流程或插件端口。[图片流程设计](image-workflows.md)明确现有文本预算、Step参数与旧格式兼容边界及实际验收目标。
