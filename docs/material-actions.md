# 统一材料与动作：下一轮实现契约

状态：分阶段开发，2026-10-17。批量文件校验、图片工具、Agent 最终回答、插件最终输出和 MCP 已完成结果到统一接力面板的直连已有显式接力能力；类型化资料库支持回收站恢复；共享材料端口、通用配方、插件/MCP 通用动作适配与范围授权写入仍未完成。

## 当前代码与缺口

`src/text_flow/material.rs`包含Text、Table、File引用和短期Image材料；文件引用只交给已声明的文件接收器，不当作文本路径解析。`src/text_flow.rs`格式1–4为串行、最多16步；格式4从有界内存图片开始，由`image.info`转为可组合JSON文本。图片在进程内暂存，不序列化到工作区快照或配方。`src/text_flow/files.rs`主动读取/保存；`src/app/handoff.rs`与`src/image_tools/relay.rs`仍承载常规结果和确认式图片接力。通用图片编辑动作、多输出和持久材料库仍未完成。现有文本/表格配方必须继续可用，不强行重新保存。

类型化资料库的删除现在先写入独立 `artifact_trash` 标记表，保留原资料行与不可变版本；旧版资料库在第一次删除时惰性创建该表，无需改变现有 schema 版本。用户可以只读查看、按当前版本/名称搜索、恢复，或二次确认后永久删除；恢复与永久删除均绑定预览时版本。永久删除会级联移除资料版本，不会删除任何源文件。回收站内不允许编辑和新建，草稿未保存时拒绝切换列表或恢复，避免覆盖用户输入。

用户允许本地保存及主动修改数据；本地优先不等于永远只读。新接口要能表达写操作，同时让普通纯计算保持便捷。

## 用户流程

1. 拖入文件、粘贴、从另一工具送入结果或选择已有材料，建立独立工作实例。
2. 操作搜索优先显示可以直接处理当前材料的动作；需要转换时展示可选转换步骤，用户选择后再加入，不悄悄改变内容。
3. 一次执行可以输出多个具名材料，例如压缩图片、缩略图和尺寸报告。结果卡显示来源、实际格式、大小、工具版本和状态；每件结果可预览、复制、保存或接力。
4. 默认新增目标；用户可以明确选择覆盖或批量修改。运行前显示将修改哪些文件、是否可恢复、预计资源及所需权限。纯计算不反复询问。
5. 失败定位到具体步骤/文件，保留已完成输出；取消停止后续操作，已落盘成品不因取消被删除。部分成功不能显示为全部完成。

## 材料数据模型

材料外壳包括稳定ID、显示名称、类型、媒体类型、实际字节数、来源工具及版本、创建时间、有效性和存储状态。预览仅是缩略副本，执行和保存不能使用截断预览。

第一轮保留Text/Table，并将File身份引用接入共享材料外壳。File保存本次明确选定的普通文件引用及身份快照；路径不是读取授权。只有显式选择了兼容接收器后才可接收，读取时重新检查文件身份和边界，源文件被替换时要求重新确认。Image仍由独立图片接力处理，计划继续适配同一材料契约：区分编码文件与像素数据，携带尺寸/透明通道/编码格式，解码前检查像素与解码内存预算。不能把任意二进制自动解释成UTF-8。

材料内容按需读取；文件大小、像素数、打开文件数、单次任务与总结果预算分别配置和检查，避免给所有媒体套用文本1MiB限制。超限明确说明可拆分/降低尺寸/调整允许范围，不无条件一次读入内存。

存储允许临时内存、用户指定文件、主动启用的本地材料库。删除库记录与删除原文件分开；清理只处理库拥有的缓存。退出后恢复草稿和材料引用不会自动执行、联网或恢复写权限。

## 动作及权限模型

动作声明稳定ID、算法版本、输入端口、具名输出端口、参数schema、效果（纯计算/读文件/新增文件/覆盖/数据库写入/联网/系统操作）、预算与取消能力。首轮保持串行链，先支持多输出及明确选定下一步的输入端口；分支图和并行执行后续实现。

权限绑定动作版本、参数摘要、具体资源及效果；变化后重新审核。用户可记住明确范围内的选择，例如指定目录的新增文件，不等于允许覆盖、删除或任意联网。插件和Agent共享此执行层，不绕过原生限制。模型建议本身不能授予权限。

新增文件沿用`local_files::save_new_moved`完整暂存与不覆盖发布。覆盖是独立能力：冻结变更计划、核对目标身份、按策略建立恢复副本，再提交；无法恢复的操作在确认前明示。恢复不能覆盖用户后续修改，也不能把所有外部命令声称为可撤销。

## 首轮基础进展

`src/material_files.rs`已提供主动选择的内存文件引用、OS文件身份与大小/修改时间复核、按动作预算分块SHA256及原文件/报告双输出。批量校验报告和原文件现可进入统一接力面板；不把路径放进预览，接收时复核身份，文件编码工具仍要求主动点击读取。该接力限于兼容目标，不代表文件可进入所有文本操作。文件身份检查不是外部写锁。

## 结构化表格结果接力

文本流程的文本结果和结构化表格结果现都进入统一的“发送结果到工具”面板。表格先显示类型化预览和行列摘要，目标限定为数据工作台；确认后通过独立表格导入创建新实例，保留单元格JSON值类型、列顺序与原有实例。超出2 MiB的材料在进入接力前拒绝。定向测试验证了目标限制、类型化JSON往返、新建实例和来源实例保留；真实暗色桌面预览完成发送、取消、重发与接收链路。材料外壳已扩展到文件引用，但通用流程动作仍只接受文本/表格；图片、Agent/MCP输出及具名多输出端口仍需后续接入。

可组合数据管线 0.20.0 也可从最终预览或任一步完整结果检查器发起同一接力。来源标记包含 `pipeline` 工具版本和步骤标签，且随材料保留可审阅的来源元数据；类型化预览会区分文本、数字、布尔和复合值。取消不改变工作流；确认后创建新数据实例，并保留原实例、输入及最终预览。该路径不自动运行目标或保存数据。暗色/浅色原生窗口交互冒烟已覆盖来源检查、取消/确认按钮所在界面及显式接收。

## 文件引用统一接力

批量文件校验的原文件输出改为打开相同的结果接力面板。文件材料预览只含文件名、大小和来源，不显示完整路径、不读取内容；目标按类型限定为文件编码检查，超过8 MiB时接收禁用。确认接收时文件编码工具再次核验身份；接收不会自动读取，用户需在目标工具内主动点击读取。Escape、取消按钮或点击遮罩都保留原校验报告，原文件仍可从来源结果重新发起接力。编码检查草稿、转换预览和源文件均不因取消而改动。

共享 `Material::File` 是内存中的文件引用，不可序列化成路径或文件内容；通用流程的动作清单仍只声明文本/表格输入。定向测试验证文件名预览不泄露路径、目标过滤、接收不读取和原始字节不变。`cargo test --lib handoff` 32项通过，`cargo check --example file_material_ui --features ui-preview` 通过；自动桌面预览在暗色和浅色主题下都验证了报告选择、接力确认、Escape取消、重发、身份复核及主动读取。代表性视口为980×900，截图归档于技术博客档案的 `screenshots/dev105-file-material-handoff/`。初次 UI 编译曾因磁盘不足失败，后续在空间恢复后重试通过；该流程验收不代表通用文件动作、材料库或 Studio 宿主接入完成。

## dev82：文件校验的实际双输出

批量文件校验复用文件材料身份核验，保留SHA256/SHA512、进度、取消和部分失败结果。文件选择支持原有拖入/路径及多文件选择器。每个成功结果可选择校验报告（版本1 JSON，含文件名、字节数和双摘要，不含完整路径），通过顶部统一结果接力送入文本、备忘或流程等既有目标。来源仍保留。

“原文件 → 编码检查”冻结此文件引用，显示目标、大小与替换草稿说明；返回保留编码检查现有草稿。确认时重新核对文件身份及8MiB上限，再进入编码检查，不自动读取、转换或保存。主动读取继续验证身份；源文件删除、替换或改变拒绝读取。超出8MiB的文件仍可哈希，但不能进入编码检查。

这是现有工具间的实际文件引用/报告输出，不等于通用配方端口、多输出分支图、材料库或图片/插件/Agent平台已经完成。

## dev83：取消与失败保留

## dev112：本机资料重新接力

本机资料库当前打开的文本版本或尚未保存的草稿可通过统一“发送结果到工具”入口重新接力。接力来源会标明资料名称、当前查看的版本、是否含未保存编辑及其原始来源标记；目标选择与接收仍经过原有预览和确认流程，接力本身不会写回资料库或自动执行目标工具。已登记的安全来源标记跨保存、重开和再接力保留；编辑正文后来源改为“本机编辑”，不再冒称原生成工具。接力沿用通用文本入口的 2 MiB 上限，超过上限时明确拒绝；更大的文件型资料仍需后续共享文件材料接口。

新增状态测试验证草稿和已保存版本都能提供准确接力快照，且预览/提取不会创建资料库文件或静默保存；来源标记在保存/重开后保留、编辑后清除。版本目录将“类型化资料与结果”提升到 0.2.0。

## dev113：工具结果进入本机知识源

统一接力面板新增“网页与对话收集”目标。普通文本结果最多 256 KiB，接收后只填入空白收集表单的内存草稿，并保留已登记工具 ID/版本作为来源；若收集器已有未处理内容或后台预览正在运行，接收会被拒绝以保护现有草稿。用户须手动准备正文预览，再选定目录型知识源并确认保存 Markdown；保存不自动扫描文件、不更新关键词/向量索引，也不触发模型请求。接收器支持明确清空表单，来源名称不附带原始本机路径或凭据。

“网页与对话收集”工具版本提升至 1.1.0。测试覆盖来源和正文进入空白草稿、超限/NUL/覆盖被拒绝、预览未自动生成及该目标在接力搜索中可发现。

## dev114：本机资料正文检索

资料库搜索现在同时匹配名称和每项资料的当前版本正文，支持任意子串及 Unicode 小写转换后的大小写不敏感匹配；CJK 按原字符子串匹配。检索只读现有 SQLite 版本记录，不建立额外正文副本、不改变索引或资料内容。为了避免 256 MiB 有界扫描阻塞界面，输入停止 250 ms 后才提交搜索，结果由单一后台工作线程串行计算，并合并积压查询、忽略过期结果；清空查询只同步加载有界条目元数据。历史版本仍可按项打开查看，但全文搜索只检查当前版本。

工具目录将“类型化资料与结果”提升至 0.3.0。测试覆盖正文子串、大小写、中文、版本替换后不再命中旧正文、未命中、控制字符拒绝以及后台查询结果回传。

## dev115：资料搜索上下文预览

正文命中的资料结果卡片现在显示命中位置附近的短上下文，最多截取前后各 36 个 Unicode 字符；控制字符在预览中替换为空格。名称命中仍不生成正文预览，空搜索列表也不携带正文片段；预览仅在后台搜索结果内存中使用，不进入 SQLite 或版本历史。测试覆盖 Unicode 大小写命中、预览上下文边界和控制字符处理。

“类型化资料与结果”提升至 0.4.0。

## dev117：结构化表格进入资料库

统一接力面板现在可将文本流程产出的类型化表格交给本机资料库。资料类型明确保存为“结构化表格”，保留列顺序与字符串、数字、布尔、null、数组/对象等JSON单元格值；不再把它伪装成普通JSON。资料库可按表格类型筛选并搜索当前正文。接收仍只创建未保存草稿；用户明确保存后才写入本机，重开时复原表格类型和来源工具版本。沿用现有SQLite schema和16 MiB单版上限，旧资料无需迁移；格式错误或列名、行宽、行列上限不符合工作台数据模型时拒绝保存。

“类型化资料与结果”工具版本提升至 0.6.0。定向验收覆盖接收不落盘、保存/重开类型保持、结构化数据往返、来源保留及表格过滤搜索。

## dev118：结构化表格从资料库再次接力

打开资料库中的结构化表格后，统一接力面板仍将其作为 `Material::Table` 发送，而不是普通文本。有效的未保存表格编辑会在当前内存快照基础上校验并发送；无效 JSON、列结构或行宽会在发送前报错，原资料及草稿均不写入。接收端仍由用户选择数据工作台或资料库并确认；工作台新建类型化实例，来源资料保留。

“类型化资料与结果”提升至 0.7.0。定向测试覆盖资料库→表格接力草稿→数据工作台实例的类型往返、来源标签及无效草稿拒绝。

## dev119：数值表格直接进入计算器

统一接力面板为结构化表格增加计算器目标。仅完整1–8行、1–8列且每格可转换为计算器数值的矩形表可用；行、列顺序固定显示在确认页，表头不作为数据传递。工作台与资料库不写回，数值会按精确分数或近似f64原类型进入选定矩阵A/B；未保存矩阵仍走既有显式替换许可，接收不自动计算。非数值或超界表格不会显示此目标，用户仍可回到数据工作台按范围选择。
