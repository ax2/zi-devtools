# 图片可复用流程与统一材料接入设计

状态：dev91部分实现，整体仍开发中；2026-10-08。原设计基于865c7ad，新增独立流程界面和动作核心，不代表所有工作实例、统一端口或插件接入完成。目标保留原程序大量工具访问、跨工具协作、主动数据操作与插件扩展的完整方向。

## 实际证据和关键决定

现有src/text_flow/material.rs只有Text/Table，Action声明单输入/单输出；src/text_flow.rs的Step只有action/version，没有参数，Definition格式1/2从Text起步，最多16步、单步1MiB/累计8MiB，不能直接承载图片。src/workflow_document.rs只识别Table/Tool，不能把新的JSON冒充已有格式2。

src/image_tools/relay.rs现有Image/Rgba/Encoded/Published输入、来源版本链、转换/裁剪目标替换审核；Published引用按明确选择时读取，并核对发布SHA。src/image_tools.rs已有16M像素/边长12000/192MiB解码/128MiB编码预算，WebP编码当前是无损，JPEG35..95。不能宣称已有WebP有损质量滑杆。

src/image_tools/editor.rs现有render_output在原图坐标中选择最后一次裁剪，其他标注也在原图坐标中执行，不能原样当成逐步流水线算法（例如连续两次裁剪相对于哪张图）。新流程每一步坐标明确相对该步输入，保持现有编辑工具行为不变，不替换已验证算法语义。

## 使用流程

用户可以从图片接力选择新建图片流程，默认新实例，来源工作保留。左侧固定输入与步骤管理，右侧可切换当前步骤结果、最终图片、实际编码信息和报告。每张结果卡显示实际格式/尺寸/字节、来源工具与动作版本、运行状态，提供接力和另存。搜索依输入类型给出可用动作；类型不兼容项显示原因，不隐式把报告JSON变成图片或二进制转Base64。

流程名、收藏、最近使用、保存定义入口复用程序既有索引；工具数量达到上百后避免新建第二套目录。保存定义不带图片内容、绝对文件路径、权限或执行结果；再次载入需重新选择输入，不自动运行。主动保存图片和流程分别是用户操作，允许本地持久化，不宣称整个程序禁止写入。

## 类型和格式

先建立带稳定ID的材料外壳，拥有Text/Table/Image/File载荷；图像使用共享不可变像素/编码Arc，缩略图只作预览。来源链区分工具版本和动作算法版本。外壳容量统计分别计编码、像素分配和结果累计保留，不能给图像套文本限制，也不能保留每步192MiB而无总预算。

新增独立判别的图片流程文档（提案kind=image-workflow、schemaVersion=1），strict未知字段拒绝；步骤包含稳定动作ID、版本、类型化参数及选定输入/输出端口。文档最多64KiB、1..16步骤，未知算法版本和不兼容链拒绝。旧文本1/2和表格格式保持原样读取和保存。流程文件不是读取、覆盖或联网授权。

首轮动作：image.crop（相对该步输入的有限0..1矩形，边界/空区域检查）；image.resize（保持比例、明确允许放大与否，默认不放大）；image.encode（PNG/JPEG/WebP，实际编码字节，不按缩略图估算）；image.info（具名JSON报告，实际编码格式/字节、尺寸/透明信息）；file.hash（已授权材料的校验输出）。报告作为旁路结果保留，下一步骤明确选择图像端口，不把JSON报告隐式当图像。

裁剪/缩放在纯Rust核心内处理，界面仅收集参数并预览；原生编辑器与流程分别适配，共享真正相同的算法部分，不复制整个State或依赖egui材质。字体标注、OCR、蒙版和Agent建议可后续扩展，须各自有真实入口和验证后再改目录状态。

## 执行、保存和恢复

纯计算不反复询问；跨工具替换旧草稿继续明确确认。输入和定义冻结到任务，切页、隐藏、关闭视图后仍可接收终态；取消绑定当前任务身份，不命中新任务。结果按步骤保存实际成功/失败/取消，过期返回不覆盖新草稿。重启恢复只恢复主动保存的定义/引用，执行和权限不恢复。

编码成功后显示实际字节数、尺寸、透明度及比较信息；另存新文件用现有完整暂存/不覆盖发布。批量输出要冻结目标列表和冲突策略，部分成功逐件说明。用户明确需要的覆盖/批量修改作为独立写入效果，必须可预览目标、检测外部变更，并说明恢复边界；不能把当前无覆盖发布当作永远禁止修改原文件。

## 推进顺序和验收

1. 提取可复用图片动作及严格参数/类型检查，测试连续裁剪坐标、透明PNG→裁剪→缩放→WebP→报告，尺寸和实际字节一致；原有图片工具及文本/表格回归保持。
2. 完成真实流程界面与新实例接力；同工具两实例草稿独立、每步预览、取消/失败保留，明暗窄窗/键盘和真实原生操作检查。只有入口与执行都验证后目录才标已实现。
3. 接入共享文档读取、主动保存/导入审核、收藏/最近/托盘；重新载入不带图片内容、写权限、不自动执行，改动/删除/链接/超限保护。
4. 对应图像材料端口再提供公共插件/Agent适配。Studio安装/Host生命周期由专门会话验收，本地候选不能代替真实Host验收。

本轮dev90先完成构建、服务与运行包冻结；本设计不会在构建尚未结束时修改产品源，以免污染可追踪构建来源。

## dev91实际接口与剩余范围

原生入口“图片流程”支持裁剪（界面百分比，定义中0..10000比例整数，相对该步输入）、保持比例且不放大缩放、PNG/WebP无损或JPEG可调质量编码、附加JSON报告。结果按步骤可选择预览，编码结果按实际解码像素进入后续步骤。图片接力可进入流程；输入替换保留步骤、清除旧结果，需手动运行。逐步累计保留结果最多256MiB，空间检查在新像素分配之前；失败/取消保留已完成步骤。

定义JSON实际字段为kind="image-workflow"、schema_version=1、steps；步骤以action判别（image.crop/resize/encode/info），version=1及各动作严格字段。定义最大64KiB、1..16步，未知字段/版本、非法矩形/尺寸/质量拒绝。独立“保存流程定义/载入流程”主动操作，导入先确认替换步骤、不自动运行，原输入保留；文件不含输入图片、路径、运行结果或授权。另存选中编码结果采用不覆盖发布。待导入确认和后台任务阻止静默退出。

尚未接入workflow_document共享文档、全局保存流程收藏/最近/托盘和独立工作实例。原有文本/表格读取不变，不把新文件冒充旧格式。信息报告可展开查看；通用具名端口、报告直接发送和文件哈希链仍待完成。该功能在目录中保持in-progress，只有验证过的实际范围才列出。
