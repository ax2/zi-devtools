# 本机向量索引

先在“本地知识源”添加文件或目录并手动扫描，再用“增量知识索引”同步全文分块。打开“本机向量索引”，确认回环地址的 Ollama 正在运行、已安装支持嵌入的模型，填写完整模型名（例如 `bge-m3:latest`），点击“同步全部已索引分块”。程序只会在这次明确操作后把全文索引中的分块文本发送给所选本机模型；Ollama 自身是否记录请求由其设置决定。

向量保存在 `%USERPROFILE%\.zi-devtools\knowledge-vectors.sqlite3`，全文与来源位置仍以原来的 `knowledge-index.sqlite3` 为准。模型名及 Ollama 模型摘要决定索引版本：同版本、同文件和分块哈希直接复用向量；变化的分块重新生成，已移除分块删除；模型摘要变化时完整重建。整轮同步在 SQLite 事务内完成，取消、模型响应异常或全文索引在同步期间变化均回滚。同步可能需要时间和模型内存；可在界面查看进度并取消，已经启动的模型计算可能继续到服务端自行结束。

输入仅允许 `127.0.0.1` 或 `::1` 的 `/api/embed`，不使用代理或重定向。单批 1–16 个分块，每段 1–4000 字符且不超过 16 KiB；单次响应最多 4 MiB，维度 1–8192；全文索引最多 100000 个分块，向量数据最多 128 MiB，数据库页数上限相当于约 256 MiB。当前按本机 CPU 顺序计算相似度，大库查询可能较慢。点击“删除本机向量索引”并再次确认可释放生成的向量文件，不删除全文索引或原文。

语义检索会先核对模型摘要，再为当前问题生成一条查询向量，按余弦相似度给出最多 10、25 或 50 条结果。只展示在**当前全文索引**中仍具有相同文件与分块哈希的命中；打开原文件还会重新核对知识源清单、扫描快照和原文件哈希。来源位置、片段与引用可复制。模型版本变化需重新同步；关键词与向量结果的混合排序仍属于独立规划，语义相似度不等于事实可靠性。
