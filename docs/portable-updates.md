# 便携版更新与恢复 0.7.0（开发中）

在程序更新页先检查发布，再选择“下载并准备便携版升级”。后台认证同一版桌面/MCP EXE的发布签名、大小与摘要，写入程序目录下独立的 `.zi-update-UUID` 暂存目录；准备不会改动正在使用的EXE。当前必须使用包含 `ZiDevTools.exe` 与 `ZiDevToolsMcp.exe` 的完整便携目录，且目标版本高于当前版本。历史无签名发布只能主动下载，不能自动安装。

准备完成后显示版本、真实程序文件总大小、工具变化及恢复副本位置。保存或丢弃未保存工作，结束录屏、托管服务和后台任务，勾选同意后点击“退出并应用更新”。主程序复制自身作为当前版本更新助手，结构化传递计划、精确进程PID/创建时间和实际配置路径；不拼接shell命令。助手最多等待三分钟，不结束主进程或其它进程。主程序没有退出、PID被复用、助手内容改变或文件被占用时拒绝更新。

## 替换与恢复

助手重新核验内置发布公钥、目标元数据、暂存内容、当前程序基线、物理目录和文件类型；使用目录级独占句柄避免多个助手并发。只操作两个EXE以及自己的暂存/恢复记录，源码、用户数据、知识索引和技术档案不在范围内。程序目录别名先解析成物理路径；输入文件、暂存目录及物理路径不接受链接/重解析点。

每个旧程序保留为 `old-ZiDevTools.exe` / `old-ZiDevToolsMcp.exe`，新内容无覆盖发布到原文件名，再校验两件目标摘要。两件文件不是单个原子提交：中间失败会检查所有当前文件/恢复副本，再恢复旧版；外部未知修改或损坏副本不覆盖，明确保留现场。受控测试覆盖第二件EXE被占用、首件替换后失败、中断后的部分提交、错误基线/暂存内容和损坏恢复副本。

升级处理结束后尝试从原目录启动已核验的程序，保留配置路径并传 `--no-restore`，不会自动启动服务。Windows文件替换成功不代表新版本功能和运行健康已验收；当前没有启动健康握手，也不会因为新程序运行后报错自动降级。用户可以在“升级记录与恢复”选择旧版并明确同意退出恢复；只能恢复与这次记录匹配的当前程序，未知后续变化拒绝覆盖。

进程中断时暂存计划、基线和 `receipt-applying.json` 仍保留。若主EXE已经缺失，可从自身暂存目录中的助手进行明确的恢复操作：

```powershell
& 'C:\ZiDevTools\.zi-update-UUID\helper.exe' --recover-portable-update 'C:\ZiDevTools\.zi-update-UUID\plan.json' 'C:\实际配置目录\services.yml'
```

这里的UUID必须使用实际更新目录名；命令只适用于该目录自身的原助手，不使用下载的新EXE。签名、助手身份、恢复副本和目标文件仍要核验。可以附加 `--no-restart` 只恢复文件；运行中程序的文件锁会阻止覆盖，不终止进程。准备被取消或失败会清理本轮自身尚未完成的暂存文件；成功准备、升级记录与旧版副本保留，不自动递归清理。

## MSI与尚未完成范围

[原生MSI归属检查](installer-ownership.md)通过已注册产品、缓存MSI及组件实际路径定位安装目录，旧包没有InstallLocation也可检查。MSI拥有的目录和默认安装位置拒绝便携替换，另一目录独立便携版可共存；残留标记/未知归属保守拒绝。新版打包模板记录实际安装位置并将旧版移除纳入Windows Installer事务，独立CI验证失败回滚；界面内[MSI升级](msi-updates.md)已接入，修复/卸载仍由用户使用Windows Installer；首次正式升级继续验收。

已接入认证增量包准备与应用；仍未提供断点续传、安装器修复/卸载界面、数据迁移/恢复、空间预算与恢复副本清理UI、启动健康自动回滚及完整电源故障恢复保证。旧目录中的README、离线文档与BUILD记录保留原样，不能拿它们当成新EXE的版本说明；本次升级记录与程序嵌入版本用于跟踪。首次线上签名发布、下载后自动升级和物理UI整条路径需正式版本进一步验收，本地受控文件事务不能替代这些验收。
