# MSI安装版认证升级 0.7.0（开发中）

程序更新页依据当前主程序的Windows Installer组件归属显示安装版或便携版升级入口。安装版点击“下载并准备MSI升级”后，后台认证同版官方签名清单与完整MSI的大小、SHA-256、产品系列/身份、x64及每用户安装范围、真实数值版本和升级事务配置。目标必须高于当前程序及原MSI产品，不接受开发版本号、同版替换或降级；历史无签名发布只能主动下载，不能自动安装。

## 准备、确认与退出

包、当前程序的助手副本及有界JSON计划写到`LOCALAPPDATA\ZiDevTools\updates\msi-UUID`。只点击准备才创建新暂存文件，查看记录不创建目录；准备失败或取消只清理自身尚未完成的已知文件。成功准备保留，当前安装目录及用户数据尚未修改。

准备后显示旧/新版本、完整MSI大小、实际安装位置、暂存位置和工具变化。保存/丢弃未保存工作，结束录屏、托管服务与后台任务，勾选同意后点击“退出并使用MSI升级”。计划绑定原产品GUID/版本、物理目录和双EXE基线，助手由当前已安装主程序复制并校验摘要；结构化传递计划、精确PID/创建时间和实际配置路径，不拼接shell命令。

助手核验自身位置/版本/内容及内置发布公钥，最多等三分钟，不结束主进程。退出后再次核验原产品与双EXE、包摘要和安装器身份，用户级独占句柄防止自己的MSI助手并发。安装期间保持暂存包只读且禁止写入/删除。安装版文件替换、缓存、注册及事务回滚由Windows Installer完成，助手不手动卸载或复制覆盖MSI目录内EXE。

## 原生进度与结果

Windows Installer显示基础进度与取消界面。安装属性保留原安装目录，抑制自动系统重启并禁用Restart Manager交互。安装器原生行为和权限仍由Windows控制，不能把启动助手当作安装成功。

- 返回0：重新核验新产品GUID/版本/组件目录和签名清单中的两个EXE大小/摘要，全部通过才启动新程序。若返回成功但文件核验失败，保存明确失败回执，提示使用Installer修复，不启动未知程序。
- 返回3010：单独记录需要系统重启；当前文件核验结果也记录，不自动重启电脑或程序。
- 取消1602、Installer忙1618、失败1603及其它返回码：复核原产品与旧双EXE。旧版完整时启动已核验旧程序，否则保留现场并提示Installer修复，不手工恢复受管理EXE。
- 重启前还会再次核验，保持实际`--config`路径并使用`--no-restore`，不自动恢复服务。启动失败单独记录，可从实际安装目录手动启动。

回执、安装器和助手保留在暂存目录，可从更新页展开“MSI升级记录”。这些目录可能成为Installer后续修复的源位置，当前不提供自动清理。中断后没有终态回执只能视为状态未知，不能推断已完成，也不自动重试。

## 验证及边界

一次性Windows托管CI使用真实WiX旧/新小夹具及临时测试公钥，直接调用生产Rust准备/安装/核验核心，验证篡改包拒绝、旧版本失败回滚/原产品双EXE恢复、成功升级、重复执行拒绝及卸载保留未知用户文件。测试公钥只在`cfg(test)`出现，生产准备和助手始终验证内置官方公钥。测试先拒绝已有产品，并只卸载本次生成的产品GUID，不在本机装卸正式产品。

该流程仍是开发版。首次正式签名Release下载→确认→真实助手及Installer界面→新程序启动、真实用户权限/文件占用/需重启环境、启动健康握手和自动回滚仍待进一步验收。文件与注册核验不是功能健康验收。尚无签名增量应用、断点续传、修复/卸载UI或数据迁移恢复；不要将CI夹具或合成截图视为这些能力已完成。
