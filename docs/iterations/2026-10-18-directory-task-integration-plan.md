# 目录对比与复制：后台任务接入计划

日期：2026-10-18。状态：已核实缺口，待实现；不代表 file-compare 1.3.0 已包含这些能力。

## 当前证据

- src/directory_compare.rs 的 background_active 仅检查扫描 receiver，没有检查 copy_receiver；预览生成和执行复制由独立 copy_receiver 承载。
- src/app.rs 的升级阻塞列表使用该方法，因此只执行复制时不会被此条目识别。
- src/app/task_center.rs 的 task_snapshots、poll_tasks 与取消注册表尚无目录对比/复制接入。结果收取位于目录页 ui()，离开该页后工作线程仍可执行，但页面状态不会通过统一轮询及时收取。
- 当前复制逐文件原子、无覆盖提交，取消后保留已完成文件；本计划不改变这些数据操作语义。

## 下一轮实现范围

1. 扫描、生成预览、执行复制采用明确任务种类，并接入 Job/RunId 运行代次；拒绝用旧任务记录取消新任务。
2. 应用循环轮询目录任务，离开页面后照常收取结果，任务中心展示状态并能返回 file-compare。
3. 单任务和全部取消复用统一注册表；复制取消只停止未完成项，不回滚已提交文件。预览取消不得被展示成复制成功。
4. 升级忙碌检查同时覆盖扫描和复制。后台运行时维持适当重绘；禁止通过重启绕过未完成写入。
5. 任务历史只保留允许保存的任务元数据，来源路径、目标路径和文件内容不写入统一本机历史。

## 验证要求

- 用临时目录与可控通道验证三种任务从 running/cancelling 到正确终态；拒绝过时代次取消。
- 用户从目录页切到任务中心后，实际任务完成状态可见，点击返回保留计划、结果与选择。
- 后台生成预览不写目标；执行取消后的成功文件保留，现有文件不覆盖。
- 无任务、仅扫描、仅生成预览、仅复制分别验证升级忙碌信号。
- 完成原生浅/深色交互截图、格式/完整测试/Clippy/Release；复用共享缓存，不自动发布或提高应用版本号。

## 接入设计核对

统一路由已将 file-compare 映射到 DirectoryCompare，因此新任务沿用此稳定 key，不新增另一套目录入口。State 内使用一个串行 Job 搭配 Scan/Preview/Copy 模式；三种工作不会并发运行，generation 区分每次操作。取消注册使用 requires_instance=false，并检查当前任务 owner/generation 的有效性。固定任务标题按操作种类选择，不拼接用户路径；现有 task_history 明确排除 summary、实例名和输入输出，接入时保留这个约束。
