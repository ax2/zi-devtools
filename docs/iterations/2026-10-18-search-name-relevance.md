# 多词搜索中的名称优先级

## 发现与证据

接力键盘验收的真实截图 `2026-10-18-handoff-keyboard-review/keyboard-dark/keyboard-94.png` 中，查询“JSON 工具”返回26个目标，前排显示Celery任务诊断、DRF OpenAPI对比、Django SQL等；底部当前选择仍是JSON。这说明搜索可用，但核心名称意图没有明显领先。截图不是排序单元测试，不据此宣称所有查询都有问题。

源码核对：registry::ToolEntry::score_normalized在精确整句ID/名称/别名、版本和名称前缀之外，先将全部词出现在版本历史中的结果记为400，再将说明/关键词组合记为300。接力发现复用该分数，同分按显示名称排序。“JSON 工具”不是JSON的完整名称或别名，且“工具”在许多条目的初始版本历史中出现，使名称工具与历史说明工具同级。

## 拟改进

继续要求每个查询词都在现有索引中出现，不丢弃“工具”等词，也不把多词输入放宽为任意一词匹配。所有词满足后，名称或ID中的完整查询词、名称中的词组合、部分名称与额外说明组合、别名与额外说明组合，应优先于仅版本历史/说明命中的结果。完整名称/ID/别名、版本与版本前缀规则保持优先。收藏、最近与使用次数只用于同等级细分，不能盖过名称相关度。

匹配原因需要反映“名称与关键词”或“别名与关键词”，不能将混合命中误称为完整名称或精确别名。接力仍保留CSV/TSV格式入口的优先级，不自动更改当前目标或触发操作。

## 验收设计

- 当前目录“JSON 工具”首位JSON；规范化全角/大小写/多余空白同结果。
- 加入不存在的第二个词后无结果，不能因为JSON精确命中就忽略其他词。
- 合成的历史命中项即使被收藏且使用很多次，也不能压过名称匹配。
- 不连续名称词、别名加说明词、仅历史词各自返回准确的匹配原因。
- 精确名称/别名冲突提示、当前/历史版本、单词拼写修正、全部路由精确搜索回归保持通过。
- 接力原生输入“JSON 工具”时直接断言首位真实接收目标是JSON，保持已经选定的目标和来源，不能只核对截图文字。
