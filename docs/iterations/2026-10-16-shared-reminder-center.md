# 统一提醒中心（时钟 0.6.0 / 日程 1.5.0）

日期：2026-10-16
程序版本：0.82.0-dev.105（保持不变）

## 目标与结果

将全功能时钟生成的闹钟、计时器、专注通知与万年历/日程到期提醒汇入同一个 UI 提醒中心。统一访问和查看，不合并底层日程数据库、时钟快照、调度逻辑或稍后策略。

提醒中心按“时钟工作台”“日程”分组。时钟项沿用知晓和固定 5 分钟稍后；日程项沿用知晓、5/10/30/60/120/1440 分钟稍后，并可直接打开对应日程。关闭窗口不确认或删除提醒。提醒仍未处理时，备忘录/日程页面顶栏和其他页面的浮动入口都能重新打开；到期通知和重启恢复的时钟提醒会打开中心。

## 修改

- 在主循环传递一致的本地/UTC时间快照后，共用提醒中心只消费两侧现有的待处理通知和操作行为。
- `Planner::ui` 保持原单参数接口；新增 `ui_with_reminder_count` 供主应用显示时钟与日程的合并数量，避免破坏既有集成调用。
- 更新时钟 0.6.0 与日程 1.5.0 工具版本及目录摘要，补充时钟、日程与产品路线文档。程序版本不变。

## 验证

- 原生 `reminder-open-smoke`：通过；从首页提醒中心打开准确的日程事件后，独立时钟通知仍留在中心。
- `cargo test --features ui-preview`：通过；覆盖 940 个库级测试及集成测试，环境相关测试按现有标记忽略。
- `cargo clippy --all-targets --features ui-preview -- -D warnings`：通过。
- `cargo fmt --check`、`python scripts/sync_tools.py --check`、`git diff --check`：通过。
- 深色和浅色 1600×1125 真实 UI 截图已检查。日程工作台内的分组、按钮和日程正文清晰；颜色对比及窗口层级可读。

## 限制与遗留

这次统一的是入口和窗口，不是统一通知存储/调度；关闭程序后仍不会弹出日程提醒。时钟知晓/稍后与日程知晓/稍后保存到各自系统。系统睡眠、系统时间变化与退出后的通知仍需独立验收。全量测试期间发现并修复了 `Planner::ui` 参数变更造成的 `planner_shared` 编译失败；兼容入口已保留。
