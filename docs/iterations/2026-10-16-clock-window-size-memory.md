# 2026-10-16 时钟小窗尺寸记忆

状态：开发版迭代完成，独立工具版本 `0.5.0`；程序版本保持 `0.82.0-dev.105`，未发布。

## 本轮改动

关闭某个时钟小窗后，在同一应用会话内再次打开同一目标，会沿用最近观察到的窗口客户区尺寸。世界时钟、秒表、各计时器和番茄专注分别记忆；缓存最多保留 48 个目标，尺寸限制为 320×260 至 1600×1200，异常尺寸回退到安全默认值。全屏和最大化期间不覆盖记忆尺寸。

布局仍是会话态：不写用户数据，不保存屏幕位置或哪些窗口曾打开，也不跨程序重启恢复。README 的程序版本未变化；`docs/tools.json` 的 `clock-workbench` 更新到 `0.5.0`，生成目录和 `docs/clock.md` 已同步。

- Windows 原生 `clock-window-smoke`：通过。真实创建计时器小窗，切换全屏/置顶并退出全屏，将窗口客户区调至 720×480，关闭后重开；验证新 viewport id、内部记忆尺寸及实际 native client rect 均恢复到目标尺寸。现有流程也验证计时器仍运行且窗口关闭后 HWND 消失。
- 全量 `cargo test --features ui-preview`：911 项通过、27 项按需忽略；全部集成测试通过。
- `cargo clippy --all-targets --features ui-preview -- -D warnings`、`cargo fmt --check`、`python scripts/sync_tools.py --check` 和相关文件 `git diff --check` 通过。

## 限制与后续

原生冒烟在当前 Windows 桌面环境验证，不能替代手动拖拽、混合 DPI、跨显示器边界和不同缩放比例验收。下一步可在满足这些桌面条件时补充跨屏布局实测；此版本不会持久化任何窗口几何。
