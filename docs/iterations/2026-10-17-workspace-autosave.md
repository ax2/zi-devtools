# 数据实例自动保存工作记录（2026-10-17）

## 目标

为已有的本机数据工作实例增加用户可控的自动保存，减少编辑或表格处理结果在意外退出时丢失的风险，同时维持默认不写盘和显式本地数据授权。

## 发现

- `workspace-sessions` 当前支持多份内存实例和用户主动保存的 SQLite 快照，但编辑修改默认不自动持久化。
- 保存内容是本机未加密数据，单项最多 64 MiB、总量 128 MiB、最多 256 项；大表的克隆和序列化需要避免占用界面线程。
- 工作台会在应用后台任务中心轮询，因此实例离开当前页面时仍可完成到期保存。

## 修改

- 每个实例分别提供“启用自动保存… / 暂停自动保存”；启用前的确认框说明本地明文存储、保存范围、容量上限、暂停行为和会话级设置。
- 自动保存默认为关闭，不写用户偏好；重启后再次明确启用。捕获用户输入事件后等待 3 秒空闲，实例任务忙碌时每秒重试；新建空实例不创建数据库，清空已有快照则保存空状态，避免重启时恢复过期内容。
- 延续现有后台 SQLite 写入、数据恢复校验和乐观版本检查。以 SHA-256 比较当前序列化内容与最近成功保存内容，跳过无变化写入。
- 手动保存与恢复结果也维护摘要，避免启用自动保存后立刻重复存储相同内容。
- 更新 `workspace-sessions` 工具目录到 0.5.0，保持 in-progress 状态；同步生成工具目录文档和数据工作实例说明。

## 遗留与风险

- 自动保存只在 UI 捕获到输入事件后调度；运行任务结束会延迟一次检查。系统强杀、退出前尚未到空闲时间或保存失败时仍可能丢失最新改动。
- 自动保存只在 UI 线程捕获有界的快照对象；表格行通过 `SharedRows` 写时复制共享，后台执行 JSON 编码、SHA-256、恢复校验和数据库写入。内容未变时跳过恢复解析和写库。
- 捕获快照仍会复制有明确字段上限的文本和小型流程定义。若用户恰好在后台保存期间修改共享表格行，写时复制会在该次编辑中复制整份行集合；大型工作实例的实际界面延迟仍需在运行环境中测量。
- 目前仅覆盖数据工作实例，不覆盖图片/文档实例、插件写操作或可恢复的执行任务。

## 后续自动保存响应优化（2026-10-17）

- 自动保存快照分成有校验的手动保存与后台构造的只读工作副本。数据表行改为透明序列化的 `SharedRows`，通过 `Arc::make_mut` 在修改时复制，保存线程与继续编辑期间各自读取稳定内容；现有 JSON 仍保持 `headers`/`rows` 数组结构。
- 摘要和完整恢复校验在后台执行；内容和名称摘要未变时跳过解析和写库。手动保存继续在发起前校验并序列化。
- 验证：`cargo fmt --check` 和 `cargo check --lib` 通过；默认与 `ui-preview` 特性下的 `workbench::sessions` 测试各 18 项通过，覆盖行存储共享、写时复制隔离、JSON 兼容和工作实例保存。当前全量 `cargo test` 通过（1,043 passed，32 ignored，0 failed），`cargo clippy --all-targets -- -D warnings` 通过。
- `python scripts/sync_tools.py --check` 和 `git diff --check` 通过。此前自动保存后台摘要版本的中间构建耗时 12 分 45 秒，EXE 为 40,971,264 字节，SHA-256：`365BD1B73F2DF9C13A80B43CC34D5B799516051547EB4278D9607D027629BB94`；随后加入共享行快照后，当前 Release 构建耗时 8 分 40 秒，`target/release/ZiDevTools.exe` 为 40,984,064 字节，SHA-256：`74728FB2FA67B0393CA2DC0E38511B74C93A0856689F5E389E4247DA035F1CA9`。版本保持 `0.82.0-dev.105`，未发布阶段版本或安装包。
- 开发机合成性能诊断：8,192 行 × 4,096 字符，JSON 快照 33,595,931 字节；两次测试均测得快照捕获 <1 ms，编码 501–571 ms，恢复 77–79 ms，保存期间编辑触发行 COW 11–12 ms。由显式 `--ignored` 性能诊断测试测得，不作为真实 UI 帧率或其他硬件保证。
