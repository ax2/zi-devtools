# 更新包生成与重建 0.1.0（开发中）

工具库搜索“增量更新”或“差分包”，可收藏、从最近使用与托盘进入。此页是本机更新包工程能力，不是已经完成的在线升级器。

## 生成与重建

1. 选择普通源文件与目标文件，填写源／目标 SemVer。目标必须更高；标签由用户填写，目前不读取 EXE/MSI 内部版本。
2. 点击“生成并自检预览”。后台建立内容分块索引，用 SHA-256 寻找可复用数据并再次比较原字节。复制和新增操作压缩成差分内容；同时压缩完整目标，对比包含包头的实际大小，选择较小包。完整内容模式不依赖源文件重建。
3. 预览版本、大小、复用量和摘要，再明确“另存新文件”。输出为独立 `.zidelta`，不是 ZIP。输入保留、不覆盖已有输出。
4. “核对并重建”选择包；差分模式另选完全匹配的源文件，完整内容模式可不选源。后台校验包头、压缩内容长度与摘要、源大小和摘要、操作范围及目标长度和摘要。成功后只在内存中提供结果，用户可另存新文件；不会执行结果。

取消或失败保留原有预览。切换表单会清除可重新生成的预览；后台任务冻结输入。未另存结果退出时提示，后台保存须等待完成或返回取消。提交点后的取消不会删除已经发布的新文件。程序完全退出后内存预览不恢复。

## 限制与文件安全

源和目标各最大128 MiB，包头最大4096字节，压缩/解压与操作数量均有上限。当前实现将输入和操作保存在内存中，大文件会有数倍于文件大小的内存占用；生成和重建在后台，可取消。

目录别名解析到真实路径，兼容工作区的目录 junction；拒绝链接输入文件和解析后路径中的重解析位置。保存先写同目录独有暂存文件、同步后硬链接提交，因此已有文件及抢先出现的文件不会被替换。文件系统不支持硬链接时失败，不退回不安全覆盖。该机制不是针对恶意并发目录替换的安装器安全边界。

SHA-256 校验只证明所声明内容一致。当前包没有发布者签名，不可以据此信任外部包或自动安装；所有头字段包括版本标签都可能由包作者填写。包内没有输出路径、脚本或执行指令。

## v1 文件格式

8字节 `ZIDELTA1` 标记、4字节小端 JSON 长度、有界 JSON 头、raw DEFLATE 内容。头包括 schema、版本标签、Delta/Full类型、源/目标/压缩内容大小与SHA-256、复制和新增字节统计，拒绝未知字段。Delta 操作：`0` + u64源偏移 + u32长度；`1` + u32长度 +原字节；`255`终止。终止后数据、未消费的压缩尾部、越界或未知操作均拒绝。Full 为压缩完整目标字节。

发布工程辅助命令（Rust，无安装行为）：

```text
cargo run --example delta_package -- create SOURCE TARGET SOURCE_VERSION TARGET_VERSION ABSOLUTE_OUTPUT
cargo run --example delta_package -- compare SOURCE TARGET SOURCE_VERSION TARGET_VERSION
cargo run --example delta_package -- inspect PATCH
cargo run --example delta_package -- rebuild SOURCE_OR_- PATCH ABSOLUTE_OUTPUT
```
