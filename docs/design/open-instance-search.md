# 当前工作实例的统一搜索

日期：2026-10-18。状态：功能已接入，本轮40阶段验证完成；补充验收范围见末尾，不计入上一轮导航历史交付。

## 要解决的问题

工具目录解决“用哪个工具”，导航历史解决“返回刚才的位置”，但用户已经打开多份数据和图片流程时，还需要直接找到指定材料。搜索工具名称只能打开该工作台当前活动实例，不能按用户给实例起的名称定位。

实施前代码调查（记录当时缺口）：

- `src/app/launcher.rs` 的 `Results` 包含工具、流程匹配、收藏流程与最近流程；`Choice` 没有当前工作实例类型。
- `src/workbench/sessions/workflows.rs` 的 `workflow_matches` 搜索已加载的流程库元数据。匹配中虽包含实例名称，但返回的是流程文件，不是单纯切换到这份工作实例。
- `src/workbench/sessions/ui.rs` 用下拉框选择数据实例；当前上限为16份。图片流程在 `src/image_tools/workflow/workspace.rs` 使用自己的下拉框，上限为8份。
- 本轮 `src/app/history.rs` 已有按路由和实例ID恢复位置的逻辑，并检查确认弹窗、数据保存/恢复、图片导入审核等状态。应提炼共同导航入口，不在搜索中再实现一套切换规则。

这说明当前存在可定位性的缺口，不说明软件已经支持同时打开上百份实例。扩大容量需要另做内存、任务和布局评估，不能只改常量。

## 交互方案

在现有 Ctrl K 搜索中新增“工作实例”范围，保留原有四个范围及 Ctrl 1–4 的含义。全部范围也可匹配实例名称，结果明确标识“当前工作实例”，避免与同名工具、已保存快照和流程文件混淆。主窗口和全局快捷面板使用同一实例结果模型与执行入口。

每行显示实例名、工具类型、当前视图及可验证的状态（当前使用、任务运行、待确认等）。不把“有内容”当成“尚未保存”，不展示或搜索表格正文、图片像素、凭据或文件全文。名称相同的实例用类型和稳定的短ID辅助区分。

空查询按本次会话最近访问排序，当前实例清楚标记；没有访问记录时保持确定的创建顺序。有查询时名称精确/前缀匹配优先，再按相关度排序，最近访问仅作同分排序。实例改名、关闭或状态变化后刷新元数据，并以稳定ID保留选中项；选中项消失后不得把同一行的新结果当作原目标直接执行。

上下键选择、Enter打开、Esc关闭，遵循已有IME门禁。结果多时使用可滚动列表并让选中行可见；980×640窗口下搜索、范围和键盘提示仍可访问。打开实例只切换位置，不运行流程，不重新读取原文件，不自动保存；成功切换进入导航历史，可后退到原位置。

## 实现边界

1. 数据和图片工作区分别提供只读元数据摘要：稳定ID、名称、实际工具ID、任务/审核状态。复用当前工作区所有权，不能复制或另建一套实例状态。
2. 搜索模块采用类型明确的实例目标，区分数据与图片，不用标题作为身份。搜索不做磁盘扫描，也不触发快照加载。
3. 提炼应用层位置恢复：先检查目标仍存在及审核状态，再一次性切换。搜索面板自身不应被误判成阻止其确认操作的弹窗；其他真正的确认/保存/恢复状态仍保留门禁。失败时保留原页面、实例和历史游标，显示可操作的原因。
4. 已保存但未打开的快照仍通过现有实例库的恢复流程处理。未来若合并搜索，必须显示“恢复已保存实例”并遵守其原有读取、容量和冲突规则。
5. 最近访问仅存当前会话的有界实例ID和顺序，不持久化输入或结果。插件只有具备版本化工作实例契约后再加入，不能把任意插件参数猜测成实例。

## 验收清单

- 真实创建多份数据/图片实例，重名、改名、关闭与搜索结果刷新正确；打开后来源输入、结果、图片像素以及任务代次保持。
- 同名工具、流程文件和实例以不同目标类型打开；搜索一个实例名称不会误读流程文件。
- 从数据A打开图片B再后退A，视图与实例精确恢复；运行中的任务持续归原实例所有。
- 搜索后目标关闭、进入审核或保存状态，执行前重新验证；失败不半切换，不创建替代实例。
- 浅深色、最小窗口、鼠标/键盘、IME组合与提交同帧，以及结果缩短后的选中项行为有原生回归。
- 搜索模型用合成的100/1000条元数据检查排序、身份和列表边界；另用当前支持容量的真实实例检查端到端行为。合成规模测试不能作为真实打开1000份材料的容量证明。
- 同步独立工具版本、目录与说明，复用现有缓存完成格式、全量测试、严格Clippy和Release；不为此自动发布应用版本。
