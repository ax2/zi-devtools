# 混合检索工作台

先在“本地知识源”手动扫描，在“增量知识索引”同步全文分块，再在“本机向量索引”明确选择支持嵌入的本机 Ollama 模型并同步向量。打开“混合检索工作台”，填写同一个完整模型名与回环 `/api/embed` 地址，输入问题，按 Enter 或点击“混合检索”。可选单个知识源、最多 10/25/50 条结果和关键词权重 25/50/75%；语义权重为剩余部分。输入、查询向量和结果只保存在当前进程内存。

每次检索从全文和语义通道各取最多 50 条候选。英文关键词由 SQLite FTS5 按相关度排序；含中文的关键词仍为完整短语字面包含匹配。语义通道先核对 Ollama 模型摘要与向量索引版本，再为问题生成向量并按余弦相似度排序。来源筛选在两个通道内执行。两个结果只有来源 ID、相对路径、片段序号、文件及片段 SHA-256 都一致时才合并；结果展示前还会核对当前全文索引，剔除过期或冲突候选。打开原文件之前另外复核知识源清单、扫描快照和文件内容哈希。

融合采用固定平滑常数 60 的倒数排名融合（RRF）：`关键词贡献 = 关键词权重 / (60 + 关键词名次)`，`语义贡献 = 语义权重 / (60 + 语义名次)`，综合分为两项之和。界面展示通道名、名次、各自贡献、语义余弦和综合分，方便理解排序来源；综合分只比较本次查询的候选，不是概率或事实可信度。索引/模型不匹配、服务不可用或取消时给出错误，不会把单通道结果悄悄标为“混合”。

检索会把问题发送到你选定的本机 Ollama；服务端日志由其设置决定。最多 120 字符、512 字节的关键词输入；查询和嵌入响应沿用本机回环、大小、维度和超时限制。[带引用的知识问答](knowledge-answer.md)可由用户明确选择混合证据模式，预览核验后再调用单独设置的问答模型；[固定样例 RAG 评测](knowledge-eval.md)可同题对照关键词与混合检索，但少量样例不能证明一般召回质量。语义近似、来源命中和引用有效都不能证明模型答案事实正确。
