# 文本差异共享核心与插件迁移

状态：已提取 `zi-diff-core/0.1.0` 并接入桌面入口。旧proposal.2模块的 `text.diff` 继续返回
`UNSUPPORTED_OPERATION`；新增[proposal.3时钟实验](../proposals/studio-fields/v0.1.2/README.md)已接入完整文本差异，但原预算240例239通过/1耗尽燃料，尚未交付插件。本文件不更改冻结契约或安装候选。

## 当前行为及必须保留的边界

2026-10-11：文本差异工具版本 1.0.1。共享核心的三组测试覆盖 144 组输入对的原报告与精确字节预算、输入边界和多 hunk 放大报告；完整工作区回归 45 组、859 通过、0 失败、34 忽略，桌面优化构建6m58s与隔离服务启停通过（1414ms、exit0、端口释放）。新增探针包含在格式检查和严格工作区Clippy中，均通过；独立Node/WASI时钟诊断5项通过。以上不证明插件协议、预算或 Host 接入已验证。

核心可选 `max_report_bytes` 在格式化写入时核对 UTF-8 字节，超限返回 `CompareError::ReportTooLarge`，不返回部分报告；桌面使用 `None` 保留完整输出。原输入错误文字保持不变，输入校验先于相等判断。此限制只控制报告内容，不是算法内存限制；后续插件还须核对 JSON 转义后的完整信封。

当前入口为 `src/dev_tools.rs::compare_text`，使用锁定的 `similar 3.2.0`。
每份文本按 UTF-8 字节最多 128 KiB，按 Rust `str::lines()` 最多 5000 行；先校验
大小和行数，再处理相等文本。相等时返回“两份文本完全相同”。不同文本使用逐行差异、3 行上下文及
“原文 / 修改后”标题，保留 CRLF、末尾换行与无换行标识的既有表现。

`TextDiff::configure().timeout(Duration::from_millis(500))` 是算法的单调时钟
截止策略。锁定依赖的 `text/mod.rs` 说明：达到截止时间后算法可改用近似差异；
当前入口不会因此返回自定义 TIMEOUT 错误。这不是整体调用严格在 500ms 返回的保证，
也不保证始终产生最短编辑脚本。提取时应保留原库策略，不另造超时错误或删除截止限制。

## 时钟与 Host 边界

锁定依赖的 `deadline_support.rs` 在默认 `std` 特性下使用 `std::time::Instant`。
若关闭 `std` 且不启用浏览器时钟特性，截止检查会返回 false，持续时间会转换为 None；
因此不能为减小 WASM 而关闭相关特性并声称仍保留 500ms 行为。

WASI 版本必须实测单调时钟导入和运行行为。独立 Node / Wasmtime 提供时钟不等于
实际 Studio Host 已协商支持；当前冻结快照没有为该操作明确约定这一要求。
Host 所需声明方式应通过新的、明确版本化的提案确定，不擅自添加权限名称，不修改
冻结 v1 快照，也不静默改变 proposal.2 的承诺。尚未协商时，已交付协议继续拒绝该操作。

独立 `clock_probe` example、`run_diff_clock_probe.mjs` 与 `verify_diff_clock.py` 已实际构建/执行，Node v26.10.0 的5项诊断通过。探针分别检查单调时钟推进、主动过期后的输入重建、36组正常比较与精确报告预算，以及完整128KiB/5000行范围、超界输入和48KiB报告拒绝；在 `compare` 模式没有直接 `Instant` 调用的情况下观测到核心546次单调时钟读取，主动过期模式4次读取，不把仅创建Instant算作算法检查。负向模式让实际 `clock_time_get` 返回 Preview1 `ERRNO_NOSYS=52`，Rust实际panic并以非零状态退出；并非测试器抛异常，也没有静默关闭截止策略。

诊断模块248438字节，SHA-256 `784a10ab36a01ab2806d5283045b9adacab3dcf6e9587d54f20df66dadbbc8e2`。证据标记 `diagnosticOnly=true`，记录Node版本和程序、模块、验证器哈希。Host必须在调用前明确协商并确保提供单调时钟；不支持时应在Host/适配层拒绝该操作，不能依赖Rust panic作为产品错误处理。后续独立proposal.3适配器已经实现实际时钟预检和结构化RUNTIME_UNAVAILABLE，但仍无生产Host协商、完整预算或安装验收，因此尚不交付。独立Node诊断不证明fuel、冷启动或生产Host接受。

10M fuel、5 秒进程期限、64 MiB 内存、2 MiB 栈和 500ms 算法截止是不同约束。
不能用 fuel 代替单调时间，也不能为通过矩阵而放宽现有预算。

## 实现顺序

1. 提取同仓完整 Rust 核心，原生入口委托同一函数。保留原函数作为测试对照；
   不减少 128 KiB / 5000 行范围，不引入其他项目或原生进程依赖。
2. 提供可选的结果字节预算。原生仍可生成完整报告；插件用有界格式化写入器生成
   报告，超预算返回类型化错误，最终序列化后仍核对完整信封。不得截断 diff 后返回成功。
3. 独立验证 WASI 编译及实际时钟行为，再形成时钟要求明确的新协议草案。现有四操作
   和 proposal.2 适配的请求、结果及旧证据保留；不将新操作默认为 Host 已接受。
4. 验证原生与真实 WASI 的固定输出、错误、报告及资源边界；通过后再推进 View、
   包元数据、独立冷启动与实际 Host / Pi 接入。

## 验证要点

- 空文本、相等文本、插入/删除/替换、重复行、Unicode、CRLF/LF、末尾换行、3 行上下文。
- 原生 128 KiB、5000 行及每个边界两侧；插件每字段 8192 UTF-8 字节仍需遵守
  原算法 5000 行限制，字节合格不代表行数合格。
- 多个相隔的变更生成大量 hunk 标题时，报告可能相对输入放大；检查结果预算与
  JSON 转义后的 48 KiB 边界，不只测试单个简单 hunk。
- 正常固定样例远离截止时间，逐字节对照原算法。主动触发截止的测试应检查差异
  能重建目标文本及既有近似行为，不把不同机器的近似报告强行视为确定性字节结果。
- 记录实际 WASI 时钟导入/失败、fuel、内存和进程回收；没有实际 Host 证明时保持
  `not_delivered`，不借独立引擎的时钟支持推导 Host 支持。


## 有界精确加速与转义预算

工具1.0.2保留完整输入、报告及近似截止语义。1.0.2基线对>=512行且LF终止/无CR检查行集合是否无交集；4096桶、8192次探测和64次哈希碰撞比较均有界，哈希仅筛选候选，完整行相等才决定交集。不能证明时回退既有算法。原生报告无JSON限制；WASI按空成功信封的实际序列化开销计算剩余JSON字符串内容预算，写入器逐UTF-8字节精确计入默认serde_json转义，超限返回错误，最终仍校验整份结果。

248项真实native/WASI功能及243项原资源预算通过，仍未验证独立冷启动/生产Host/View。接近预算的大输入仍需后续压力验证；不将固定向量通过写成所有合法输入均通过。

1.0.3初次优化（历史记录）：无交集路径扩至128行，并允许CRLF与LF混合；仍检查裸CR，防止与similar的CR分词语义不一致。243预算和248功能通过，扩展15例11预算通过/4失败；新版本完整桌面与冷启动待验证，不沿用1.0.2的冷启动结论。


1.0.3后续优化保留裸CR的正确分词：该路径使用锁定similar公开tokenize_lines，LF/CRLF用原始LF切分；分行函数泛型单态化，避免运行时枚举迭代器开销。输入限制按LF字节计数加非空无尾LF的一行，与str::lines的21,845个组合对照全部相同。无交集路径先检查8个边界行，若已发现完整共同行立即回退。

短行路径（单行<=64字节、总行>=128，LF/CRLF）采用4096桶/16384探测/64次完整哈希碰撞的精确编号，哈希相同始终比较完整行，按首次old再new出现顺序分配u32 ID，与IdentifyDistinct一致；超出探测或形状范围回退原TextDiff。继续调用原Myers/Compact/Replace及500ms截止、group_diff_ops(3)和UnifiedHunkHeader；末尾缺换行提示、完整原始行与报告预算均保留。
