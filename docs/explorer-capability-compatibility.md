# 菜单能力与多安装版本共存：扩展前设计

状态：静态声明生产与只读检查已实现为0.24.0候选；逐安装能力接管、账本和恢复迁移仍待实现。不是已复现的当前11动作故障。

## 当前事实与后续风险

菜单规划使用`zi-shell-core/src/explorer.rs`中的共享`Target::ALL`。安装记录保存身份、代次、程序路径、配置路径、程序版本和摘要，没有逐安装的接收动作清单。联合事务按当前维护程序的规划器生成目标菜单。

因此，在未来新增图片等接收动作时，需要先解决旧安装共存：新MSI卸载后，旧便携版可能接管入口；失败回滚也可能恢复旧程序。不能把新维护程序支持的全部动作自动指向旧程序。当前已验证的11动作没有增加，本轮只读探针不改变产品菜单或CLI，因此此文不声称现有11动作已出现兼容故障。

## 目标行为

- 菜单只显示当前活动程序明确支持的动作；切换、接管、迁移及回滚使用该程序的能力快照。
- 程序版本不变但工具迭代时，仍可通过程序摘要、安装代次和能力协议跟踪差异。
- 预览展示动作变化，用户确认后才联合提交；失去某些动作不删除文档或草稿。
- 未知能力协议拒绝猜测，保留原登记和恢复证据；不得把未知当作全部支持。

## 候选实现与待确定项

优先评估在EXE中嵌入有界版本化能力资源，由构建时共享动作目录生成。登记时只读解析资源并绑定程序摘要，保存到安装记录；不要为了预览而运行未知EXE查询能力。资源只是程序声明和一致性证据，不是发布者认证。PE资源解析仍需独立边界、大小及编码校验。

2026-10-12实际实现选择桌面main专属的只读、不可执行`.zicap` PE节。现有winresource资源链接到根crate全部二进制；若直接使用该路径，MCP也会错误声明桌面接收器。构建脚本从共享Target表生成小型声明，只有桌面入口引用；读取器直接seek/read有限PE头和节，不加载模块或查找依赖。实际debug桌面11动作匹配、MCP无声明、此前release无声明均已通过只读检查；旧程序的缺失声明表示未知，不能作为新功能授权。详见[格式与证据边界](explorer-capability-declaration.md)。这一步尚未改变安装记录或菜单生成方式。

既有无能力字段记录需要明确迁移策略。不能仅凭长期不变的dev版本推导支持范围，也不能默认套用新程序的`Target::ALL`。旧账本/日志解码器当前拒绝未知字段，升级必须同时设计新旧协议、恢复日志及回滚行为；不能只给结构体添加字段并宣称兼容。

工具插件还需要独立输入/输出契约，不能把能显示菜单等同于插件或Host已验收。本阶段先解决本机安装间的动作兼容，不修改Studio项目或导入其私有协议。

## 必须补的实际证据

1. 旧程序只支持A、新程序支持A+B时，升级显示A+B；移除新程序后旧程序接管只显示A，实际调用成功。
2. 新程序执行后失败，旧文件和MSI归属回滚后，菜单能力也回到A；保留后来便携登记与用户选择。
3. 相同应用版本、不同动作集合能正确区分；预览后文件/能力资源/用户/账本变化拒绝陈旧确认。
4. 未知字段、损坏/过大的资源和无资源旧程序按明确策略处理，不执行程序探测，不清理未知内容。
5. 增加动作后仍验证完整UI、静默安装、两种移除顺序和真实Shell解析/调用。
